## 구조·화면 관찰과 한계

- 보드는 고정 `int[42]`와 열 높이 `int[7]`, 문자열은 `Dictionary.TryGetValue`, 스테이지는 배열 인덱스로 접근한다. 문자 조회마다 전체 데이터 목록을 반복 검색하는 문제는 발견하지 않았다. 보드 규칙·탐색은 Unity UI와 분리되어 있다.
- AI는 반복 심화 negamax와 내부 alpha-beta 가지치기를 구현한다(`AiSearch.cs:73~112`). GameApp은 `Step(16)` 호출 묶음에 약 4ms 목표와 활성 시간 650ms 제한을 두고 프레임을 넘긴다. 제한 확인 사이의 실행시간까지 엄밀히 보장하는 구조는 아니며 실기기 측정은 없다.
- 탐색 자식마다 보드 복제(보드 객체·두 배열·승리 목록), `Score`, iterator 할당이 있다. 루트 후보마다 전체 alpha-beta 범위를 다시 시작하고, 즉시 승리/방어 사전탐색은 `NodesVisited`/yield 밖에서 동작한다. **할당·추가 탐색은 코드로 확인했지만 지연·GC 결함은 측정하지 않았다.** 변경 필요성은 목표 기기의 시간/할당량으로 판단한다.
- `RefreshBoard`의 42칸 × 승리 칸 순회와 `RefreshLobby`의 `GetComponentInChildren<Text>()`가 있다. 호출 시점·데이터 크기가 제한되어 있어 병목으로 단정하지 않는다.
- 기존 720×1280 로비·대국·설정 캡처는 어두운 배경/민트/산호색과 버튼 양식이 일관되고 주요 문구가 잘리지 않는다. 돌의 ‘나/AI’ 표식도 보인다. 영어 길이, 작은 실제 화면, 터치 자연스러움, 사람의 이해도는 미검증이다. 캡처의 스테이지 제목은 과거 데이터이므로 최신 데이터 증거로 사용하지 않는다.
- 데이터는 로컬 Resources, 진행은 PlayerPrefs, 기본 광고는 즉시 Unavailable을 반환한다. 오프라인 핵심 플레이를 위한 구조는 유지되어 있다. 새 번역 선택과 플랫폼 호스트의 오프라인 동작은 아직 실행하지 않았다.
