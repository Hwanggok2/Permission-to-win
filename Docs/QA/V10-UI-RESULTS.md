## 독립 검사 연결 계획

[타이밍/취소 입력](../../Tests/Fixtures/rank-v10-ai-timing-cases.json)은 의미 기대값이다.12개 활성시간 모델·취소5개·화면3개,총20사례를 준비했다.1초=1000ms는 인계 목표의 reference이며 동결 구현 상수와 프레임 오차 허용을 명시해 바인딩한다. 문서의100/650ms 탐색 완료는 모델 입력이지 실제 AI 측정 결과가 아니다.

기존 실제 `AiSearch`와 수동 코루틴/시계 기반을 재사용한다. 일반 AI의 턴 시작·탐색 완료·최초 응수 시각,각 suspension 구간,현재 판/검색 identity를 독립 관측해 누적 활성 시간과 비교한다. 코드를 그대로 복사한 타이밍 oracle 대신 입력 사건 구간의 합을 사용한다.1초 전체기다림+탐색의 직렬 처리가 생기지 않는지 별도 확인하며,실제 native 프레임/기기 성능은 Client 타임라인 범위다.

필요한 동결 자료는 새 RankGameApp/타이밍 보조 코드·최종해시,실제 지연 상수/clock 위치·Suspended 조건·취소 identity·힌트 제외 경로,toast 프리팹/1080 기준 UI 파일,새 군모 자산/참조,Client 전체/영향 Unity XML·타임라인·한영1080/390/320 이미지,사용자 타이틀 선택과 최종Data 변경 목록이다. Runtime/데이터가 같고 군모/배치만 바뀌면 소스 검사를 반복하지 않고 해당native/자산 증거만 연결한다.
