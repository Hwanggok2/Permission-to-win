# 로비 재디자인 독립 검토

2026-10-18 KST. 사용자 요청: 하단 멀티 버튼 전체 폭 복원과 우측 실제 PvP 레이팅, 상단 도움말 옆 광고 제거 이미지 아이콘, 배경 없는 큰 물음표/설정 아이콘, 부대 도트 분위기의 스테이지 카드와 멀티 버튼. 구현은 총괄, 독립 검토자는 소스·증거를 읽고 이 문서만 수정한다.

## 사전 설계 검토

- 하단 멀티 버튼은 구매 여부와 무관하게 전체 폭을 유지한다. 좌측 멀티 행동과 우측 내 레이팅을 별도 텍스트 슬롯으로 나누고 레이팅은 별도 버튼처럼 보이지 않게 한다. 긴 영어와 큰 점수도 행동명 영역을 침범하지 않아야 한다.
- 광고 제거는 도움말 옆에 이미지 아이콘으로 이동한다. 아이콘의 시각 크기와 입력 크기를 구분해 투명 44–48px 입력 영역, 서로의 간격, 키보드 선택 표시를 유지한다. 구매자에게 숨길 때 다른 행동이나 제목이 흔들리지 않도록 한다.
- 물음표/톱니 배경을 제거하더라도 병영의 밝고 어두운 부분 모두에서 식별 가능해야 한다. 도트 외곽선 또는 밝은 실루엣 등으로 대비를 확보한다. 버튼 배경을 제거한 것을 입력 영역 제거로 구현하지 않는다.
- 카드와 멀티 버튼의 도트 장식은 평평한 테두리·번호 탭·선택 표시처럼 작은 요소에 집중한다. 문자 영역에 강한 질감이 들어가거나 장식이 잠금·완료·선택 구분을 대신하지 않도록 한다. 선택·잠금은 색만으로 구별하지 않는다.
- 표준 화면의 2.5줄 목록 구조를 유지한다. 짧은 호스트에서는 기존처럼 목록 높이가 줄어도 주요 행동이 화면 안에 있어야 한다. 상단 세 아이콘과 제목의 충돌을 특히 검사한다.

## 실제 PvP 레이팅 데이터 주의점

현재 소스에서 서버 `auth` 응답은 토큰만 제공하며, 이어지는 `type=state`가 본인의 `playerId`, `rating`, `rankKey`를 제공한다. `preview.rating`은 초대한 상대 점수다. `OnlineState.rating`의 기본값 200이나 스토리 AI Rating을 실제 본인 점수로 표시하면 안 된다.

- 기존 플레이어는 본인 서버 state 또는 인증된 프로필로 확인된 점수를 로비에 표시한다. 대국 결과 뒤 퇴장으로 현재 state가 null이 되어도 확인한 점수를 보존한다. 기존 플레이어의 조회 전/실패는 미확정 표시로 구분한다. 토큰 없는 신규 플레이어의 200은 서버 계약의 초기 점수 미리보기이며 획득한 실제 이력으로 취급하지 않는다.
- 로컬 캐시를 쓴다면 같은 플레이어와 연결된 마지막 확인값이어야 하며, 로그인/플레이어 교체와 인증 실패 때 다른 사람의 값을 남기지 않는다. 값의 로컬 보존은 서버 판정의 대체가 아니다.
- 현재 `Server/src/multiplayer/worker.ts`는 같은 플레이어의 새로운 WebSocket 인증 때 기존 소켓을 `4001 OTHER_SESSION`으로 닫는다. 별도 로비 조회 소켓을 자동 생성하면 다른 탭의 대국을 끊을 수 있다. 기존 연결에서 받은 확정 state를 유지하거나, 대전 연결을 점유하지 않는 별도 조회 설계가 필요하다.

## 상태

현행 소스와 이전 로비 캡처를 바탕으로 설계·데이터 위험을 총괄에 전달했다. 아래 보완 후 최종 소스·Unity 결과·16개 PNG의 독립 검토를 완료했다. 실제 서버 상태나 인증정보를 직접 조회하지 않았으며 게임 소스·이미지를 변경하지 않았다.

## 1차 구현·증거 검토

- `OnlineLobbyProfile.cs`는 GET `/v1/profile`을 이용하고 서버 확정 `state` 수신 때 로비 점수를 갱신한다. 초대 `preview`는 반영하지 않으며 프로필 요청 후 새로운 대전 state가 도착하면 version 비교로 이전 응답을 무시한다.
- `Server/src/multiplayer/profile.ts`는 익명 초기값 또는 인증된 플레이어의 점수를 읽기만 한다. 등록·재접속·매칭·소켓 인증/교체·저장 쓰기를 호출하지 않는다. worker의 응답에는 `no-store`와 허용 origin CORS가 적용된다.
- 1차 Unity XML은 **9/9 통과**로 확인했다. 로컬 `profile-local.json`은 7개 검사, 익명 200·잘못된 식별자 거부·CORS·기존 소켓 보존·승부 후 184/216을 기록한다. 이는 총괄의 로컬 HTTP/WS 실행 증거이며 공개 서버에 배포됐다는 증거가 아니다.
- 최초 `ko-1-lobby`, `en-3-lobby`, `ko-0-lobby`, `en-high-rating` PNG를 열어 카드 계층과 전체 폭 멀티/점수 구분, 99999점 표시가 겹치지 않는 것을 확인했다.

독립 수정 요청:

1. TV/사물함의 어두운 부분과 검은 물음표·톱니가 겹쳐 식별력이 낮다. 기존 한 방향 Shadow 대신 크림색 사방 도트 외곽선 등으로 대비를 확보하되 버튼 배경은 만들지 않는다.
2. 새 어두운 카드 헤더에서 검정 잠금 스프라이트가 묻힌다. 검정 원본에 밝은 Image tint만 적용하면 밝아지지 않으므로 밝은 잠금/완료 실루엣이 필요하다. 현재 단계도 형태로 구분하면 선택 상태가 색에만 의존하지 않는다.
3. 로비 레이팅 캐시가 플레이어/식별자와 연결되지 않고 초기화 후 토큰 변경을 재확인하지 않는다. 일반 네트워크 실패에서는 마지막 확인값을 유지하되 401·식별자 변경에서는 이전 값을 —로 바꾸고 새 본인 프로필과 연결하는 것을 권고했다.

위 3개 요청은 아래 최종 검토에서 해결을 확인했다.

## 보완 후 최종 소스·실행 검토

- 물음표·톱니는 흰 마스크 기반 새 도트 스프라이트에 어두운 본체와 크림색 사방 Outline을 적용했다. 단방향 Shadow와 어두운 배경의 겹침 문제가 개선됐다. 입력 영역은 투명으로 유지한다.
- 카드 헤더의 잠금·완료·현재 단계를 별도의 밝은 도트 잠금/체크/화살표로 구분한다. 검정 원본에 색을 곱하던 방식에서 변경돼 실제 캡처에서도 밝게 보인다.
- 레이팅 캐시는 현재 식별자의 해시와 연결한다. 식별자가 달라지면 이전 표시값을 초기화하고 일치하는 캐시만 사용한다. 401 응답은 캐시를 삭제하고 —로 표시하며 일반 네트워크 실패에서는 마지막 확인값을 유지한다. 응답 대기 중 state가 갱신되거나 식별자가 바뀌면 이전 HTTP 응답을 적용하지 않는다.
- HTTP 조회는 계속 읽기 전용이다. 인증값은 요청 헤더로 전달하고 URL/로그에 쓰는 경로를 추가하지 않는다. 독립 검토자는 실제 값이나 저장 인증 파일을 열지 않았다.

[최종 Unity XML](../../Client/Evidence/lobby-redesign-20261018/unity-tests.xml): **9개 중 9개 통과, 실패/skip 0개**. 로비 표시·직접 안내·구매자 상태·자동 홍보 우선 흐름·목록 접근·서버 state 반영·초대 preview 제외·언어/퇴장 후 점수 유지·실제 HTTP 조회·식별자 변경/401 처리를 포함한다. 총괄이 실행했으며 독립 검토자는 최종 소스와 결과 XML을 확인했다.

[로컬 프로필 검사](../../Client/Evidence/lobby-redesign-20261018/profile-local.json)와 [공개 프로필 검사](../../Client/Evidence/lobby-redesign-20261018/profile-public.json)는 각각 **7개 성공**을 기록한다. 공개 기록은 익명 200, CORS, 잘못된 식별자 거부, 활성 대전 소켓 보존, 실제 승부 후 184/216을 포함한다. 공개 서버 배포·HTTP/WS 조작은 총괄 수행이며, 독립 검토자는 전달된 증거를 읽었다. 이 서버 증거를 최종 WebGL 배포 증거로 대신하지 않는다.
