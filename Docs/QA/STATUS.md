## 최종 브라우저 관찰

총괄이 셰이더 수정 후 로비·대국 시작·플레이어 착수/AI 응수·NoFill 후 입력 유지·쉼→로비·설정·라이선스 표시/스크롤을 확인했다. 라이선스 X는 동일 빌드의 실제 중심 클릭으로 정상 동작했고, 최초 클릭 실패는 좌표 오류로 정정됐다.

CSS 수정 후 **390×844 viewport에서 canvas 390×693.333, y=75.333**으로 측정했고 로비·7열 보드·결과 잘림이 없었다. desktop 1280×720 정상 표시도 보고됐으며, 좁은 화면 검사 후 viewport override를 reset했다. 실제 기기 안전영역을 검사한 것은 아니다.

스테이지 1에서 0기준 열 수순 **3,3,3,3,1,1,2,1,4**로 9수 승리 → 연결 성공 결과 → 로비 **2/30 해금**을 확인했다. 페이지 reload 후 **STAGE 02 / 두 돌 잇기·2/30 해금** 복원도 확인했다. 관찰한 콘솔 error/warning 목록은 `[]`로 보고됐다. 원본 스크린샷·콘솔 파일은 QA에게 전달되지 않아 브라우저 기록은 총괄 보고 출처를 명시했다.

## 최종 버전 연결

[최종 스냅샷](Evidence/qa-integration-final-20261014/results.json)에 코드·데이터·그래픽/프리팹·Unity 로그·산출물 해시를 기록했다.

- 보드/AI/데이터 검증/저장/광고 소스 5개는 core v4와 같고, 변경 GameApp은 UI v1 제한 회귀 스냅샷과 같다.
- Excel/exporter·검사 의존 파일 및 생성/임포트 데이터는 data v2와 같다. Client/Generated 3파일이 일치하며 30개 경로 검증 데이터도 동일하다.
- stages.json SHA-256: `2D04B124A42F0F3798AD942E9AACAB97EE34A25F05B380144CD70F75C3904992`.
- Android APK: **34,676,997 bytes**, SHA-256 `8a809c7b1942e16d3b846721118a49d4e557cd24ea424e66d07c4d7c908c5688`.
- 최종 WebGL index.html: **3,432 bytes**, SHA-256 `2102bd16456f5bbd5788ffab1107cb611f875b9dc211472218c7044cbab23102`.
- BuildReport의 Bytes와 실제 APK 파일 크기는 같은 값으로 취급하지 않는다. 빌드 내부 데이터 추출/설치·실행 검증과 로컬 파일 해시 확인도 구별한다.

30 FPS·AI p95 500ms 등은 QA 제안 목표다. 판 중앙값 45~120초, 5명 중 첫 합법 수 30초 내 4명·자발적 추가 판 3명·패배 이유 납득 4명·오터치 0건은 총괄 목표다. 어느 것도 사람 플레이/실기기 측정 실적으로 쓰지 않는다. 작은 표본으로 유지율·광고 수익을 입증하지 않는다.

30개 승리 예시는 GameApp의 기기별 **650ms 계산 상한**을 적용하지 않은 탐색 완료 정책이다. 실제 기기는 AI 수가 달라질 수 있다. 예시는 최적 상대에 대한 강제승리나 인간의 재미/난이도 적절성을 증명하지 않는다.
