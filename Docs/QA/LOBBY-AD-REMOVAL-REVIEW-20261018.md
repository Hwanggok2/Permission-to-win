# 로비 광고 제거 버튼 독립 검토

2026-10-18 KST. 사용자의 추가 요구는 닫은 광고 제거 패널을 로비 버튼으로 다시 여는 것이다. 총괄의 구현과 분리한 UI·행동 검토 기록이다. 독립 검토자는 구현 코드를 수정하지 않고 이 문서만 작성한다.

## 설계 검토

- 기존 로비 하단의 680×110 기준 영역을 멀티 420×110, 광고 제거 244×110, 사이 간격 16으로 나누는 안은 적절하다. 스테이지 2.5줄과 도움말·설정·제목의 위치를 그대로 두며, 320px 화면에서도 두 행동의 44px 이상 높이와 레이블 폭을 확보할 수 있다. 이는 배치 계산이며 실제 프리팹의 검사 결과와 구분한다.
- 미구매자의 광고 제거 버튼은 로비에서 찾을 수 있어야 한다. 검증된 구매자의 버튼은 숨기고 멀티 버튼을 기존 전체 폭으로 복원하는 것을 권고했다.
- 자동 홍보와 직접 열기를 구분한다. 자동 홍보는 기존 지원/상품/권리/이전 실행 완료/실행 1회/안전한 로비 조건을 유지한다. 직접 열기는 횟수 제한 없이 가능하고 그 실행의 자동 표시 기회를 소모한다.
- 현재 미연동 빌드의 직접 열기는 안내만 제공한다. 임의 가격을 만들지 않고 `coming_soon`의 준비 중 표시와 구매·복원 비활성 상태를 사용한다. 실제 결제·권리 지급을 제공한다고 안내하지 않는다.
- 직접 연 패널도 X·외부·보조 닫기·Escape로 바로 닫을 수 있어야 한다. 구매 요청 중 닫고 재열어도 기존 요청 토큰과 대기 상태를 보존하고 새 구매를 만들지 않는다.

## 현재 검토 상태

설계·소스·Unity 실행 결과·15개 캡처의 독립 검토를 완료했다. 구현과 Unity 실행은 총괄 담당이며 검토자는 소스/결과 XML을 읽고 PNG를 직접 열어 확인했다. 실제 광고/IAP 연결과 공개 웹 배포는 이 작업의 검증 완료로 주장하지 않는다.

## 최종 소스 검토

- `AdRemovalOffer.OpenFromLobby()`는 직접 열기 기회를 제한하지 않으며 그 실행의 자동 홍보 기회를 소모한다. 기존 자동 홍보의 `Ready` 조건은 유지된다.
- `manualOpening`으로 미지원 안내를 열어 둔다. 지원 여부·권리 확인·상품 가격이 변하면 문구와 구매 가능 상태를 갱신한다. 준비 전에는 가격 대신 `coming_soon`만 표시한다.
- 직접 열기와 닫기는 `busy`, `statusKey`, 구매 요청 토큰을 초기화하지 않아 검증 대기 주문을 중복 생성하지 않는다. 완료 콜백만으로 구매 권리를 지급하지 않는 기존 계약도 유지한다.
- `CanOpenAdRemoval`은 도움말·설정·상세·온라인 패널·광고 처리·백그라운드 상태에서 직접 진입을 막는다. 다른 화면으로 이동하면 열린 패널을 닫는다.
- 검증된 구매자는 진입 버튼을 숨기고 멀티 버튼을 기존 680 폭으로 복원한다. 숨겨지는 진입 버튼에 키보드 포커스가 있으면 멀티 버튼으로 옮긴다.
- 에디터 제작 도구는 저장된 `Lobby`, `AdRemovalOffer`, `RankAppRoot`와 직렬화 참조를 갱신한다. 런타임에 버튼/UI 트리를 새로 만들지 않는다. 목록·도움말·설정의 위치 계산은 유지한다.

## Unity 자동 검사

[unity-tests.xml](../../Client/Evidence/lobby-ad-entry-20261018/unity-tests.xml): **13개 중 13개 통과, 실패 0개.**

- 신규 4개: 직접 재열기와 자동 재홍보 차단, 미연동 안내와 Ready 전환, 구매 대기 보존과 구매자 포커스/폭 복원, 한영·호스트 레이아웃.
- 기존 9개: 첫 실행/복구 저장, 로비 광고의 늦은 콜백, 자동 홍보 조건, 초대/화면 전환 우선, 구매·복구·검증 권리, 목록 끝 접근과 상세 차단, 처음 도움말 회귀.
- 두 로비 행동의 최소 48px 높이/44px 폭, 화면 안 위치, 서로와 목록의 비겹침, 레이블의 가로·세로 범위 및 미지원 구매 비활성을 검사했다.

이는 저장 프리팹과 테스트 어댑터를 이용한 Unity 자동 검사다. 실제 구매/복원·실광고·플랫폼 계정·공개 웹 링크 검증은 포함하지 않는다.
