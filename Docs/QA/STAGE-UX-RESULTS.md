## 구형 저장 fixture

[Tests/Fixtures/stage-ux-legacy-saves.json](../../Tests/Fixtures/stage-ux-legacy-saves.json)에 구형 raw JSON8개와 최초설치1개를 준비했다. 신규 완료 필드 이름을 임의로 넣지 않았고 `expected.highestActuallyCompletedStage`는 **검사 의미 이름**이다. 실제 런타임 필드명이 아니다. 신규 저장 필드/이행 표식이 확정되면 실제 API에 연결한다. 이 파일의 JSON 구문 확인은 제품 이행 검사 통과가 아니다.

완료 필드 누락과 명시적값을 구별하는 방식은 실제 Unity `JsonUtility`에서도 확인해야 한다. 독립 하네스의 `System.Text.Json`은 필드 초기값/누락 처리에서 native Unity와 같다는 보장이 없다. Client에 raw 구형 JSON→신규 저장→재로드 및 마지막30완료 native 검사를 요구하는 근거다.

## 주요 위험과 아직 확정할 경계

1. **완료 과대표시:** 해금30을 완료30으로 계산하거나 새 저장의 완료30을 이행29로 낮추는 것. `completedMatches`는 승리 수/완료 단계 수가 아니므로 완료 진척 대신 사용하면 안 된다.
2. **구형 정보 손실:** 저장 버전/키 교체·이행 기본값 때문에 언어, 음향, 경기/광고 카운터, 처리ID를 잃을 수 있다. 이행만으로 새경기나 전면광고 표시가 생겨서는 안 된다. 손상 저장의 복구 원본 보존도 유지한다.
3. **선택과 시작 불일치:** 챕터 탭·노드 클릭 listener 캡처 오류나 이전챕터 index 잔존으로 다른 단계/잠금 단계가 시작될 수 있다. 1/10/11/20/21/30과 모든30노드 매핑을 확인한다.
4. **결과 중복/광고 경계:** 주요CTA를 바꾸면서 기존 listener가 겹치거나 숨겨진 행동이 활성화되어 두 판을 만들 수 있다. 정상 승리/패배/무승부와 광고대기·늦은콜백을 함께 확인한다.
5. **작은 화면:** 가용 높이411px에서 지도·선택 설명·시작·도움말을 전체 축소하면 노드/버튼44px 또는 캡션 가독성을 잃을 수 있다. 클릭 영역과 보이는 작은 번호는 별도다.
6. **도구의 낡은 기대값:** 기존 `LocalizationChecks`의123개 고정값, 이전 `MakeApp`의 UI참조/자동0단계 시작, 저장 대체직렬화가 새계약과 충돌할 수 있다. 하네스 컴파일/구성 오류를 제품결함으로 등록하지 않는다. 신규 실제 필드가 존재한 뒤 필요한 대체 API만 최소추가한다.
7. **확정 필요:** 마지막30승리의 주요CTA 문구/행동, 잠금노드의 선택/설명 허용 여부, 신규완료필드/이행표식, 모순·범위외 저장값의 정규화/복구 정책. 지금의 필수 불변조건은31진입·잠금우회·완료과대주장·기존정보손실 금지다. 상세 계약 전 제품 실패로 단정하지 않는다.

## 구현 동결 후 체크 시점

반복 폴링이나 Unity/브라우저 중복 실행은 하지 않는다. 다음 자료가 갖춰지면 실제 코드와 계약에 맞춰 한 번의 영향 범위 검사를 진행한다.

- Client가 완료필드/이행 규칙·노드/챕터/결과CTA API 및 저장 프리팹 작업 완료를 알린 시점.
- 데이터14키 목록·한영내용·포맷 인자 계약, 실제 Generated/Client 반영과 데이터 검증 결과가 나온 시점.
- 독립 저장/노드/CTA 검사를 추가하고 기존 `save.`·`app.`·광고·다국어 관련 검사를 함께 실행한다. 보드/AI/stages가 동일하면 기존1,000국면·30단계 경로탐색을 반복하지 않는다. 변화가 있으면 해당 부분만 범위를 넓힌다.
- Client native JSON/프리팹/노드매핑/320픽셀 검사의 XML·캡처와 최종 빌드가 나온 시점에 제공증거를 보존한다. 이후 총괄 브라우저 실제 클릭·챕터/잠금/결과/복원 자료를 같은빌드와 연결한다.

현재 새 기능 통과/실패 및 결함은 판정하지 않았다. 기존 QA-009 종결과 출시 차단 상태를 유지한다.
