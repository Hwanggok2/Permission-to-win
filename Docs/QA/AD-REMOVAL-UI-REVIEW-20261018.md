# 광고 제거 홍보 패널 독립 UI 검토

2026-10-18 KST. 총괄의 제작과 분리해 코드·계약·노출 흐름을 검토했다. 사용자는 시안 수정과 아래 광고 빈도를 확정했다. 저장 프리팹 구현과 테스트 어댑터를 이용한 Unity 검증은 아래 최종 결과로 확인했다. 이 문서는 실제 구매·실광고 연결, 실제 기기 구매 또는 공개 배포 완료를 뜻하지 않는다. 독립 검토자는 구현 코드를 수정하지 않았다.

## 현재 기준과 범위

- `Client/Assets/StageGame/Scripts/Platform/Advertising.cs`의 기본 어댑터는 `NoFillAds`다. 현재 클라이언트에는 실제 상품 조회·권리 조회·IAP UI 연결이 없다. 현재 공개 WebGL과 무광고 원스토어 빌드에는 홍보 패널·구매 경로를 표시하지 않는다.
- 최신 사용자 지시: **스토리 정상 대국 종료마다 전면광고 1회, 멀티는 대국 이후 방을 나와 로비로 돌아갈 때만 최대 1회, 리매치 중에는 없음.** 이전 첫 3판 보호·2판/90초 및 최초 6판·이후 3판/180초 제안은 새 검토 기준에서 폐기한다. 검토 시작 시점의 `AdPolicy`와 `CONTRACT.md`는 아직 이전 값이므로 코드·Excel·생성 결과·계약의 동시 갱신이 필요하다.
- 시안 수정 확정: X의 외곽선을 없애고, **“구매하면 전면·배너 광고가 영구적으로 사라집니다”**를 표시한다. X의 44×44 입력 범위와 키보드 탐색 시 식별 가능한 상태는 유지한다.
- 상품은 1회 구매 1종이다. 전면·배너·보상형 광고를 제거하고 힌트는 판당 1회 광고 없이 제공한다. 무제한 힌트, 다른 플랫폼으로의 권리 이전, 게임 진행도 동기화를 약속하지 않는다.
- 이번 전면 홍보는 자체 광고 제거 상품 안내다. 외부 광고 SDK의 전면광고와 종류·노출 카운터·정책을 혼동하지 않는다.

| 항목 | 독립 검토 권고 |
| --- | --- |
| 첫 실행 | 첫 실행 전체에는 미노출. 저장을 읽지 못했거나 실행 횟수가 불명확해도 미노출을 기본값으로 한다. |

| 1회 소진 | 실제 표시 시 그 실행의 홍보 기회를 소진한다. 닫기, 결제 취소, 상품 재조회, 언어 변경으로 다시 표시하지 않는다. 안전한 시작 시점을 지나쳤다면 해당 실행에서는 생략한다. |

## 조작과 정보의 우선순위

1. 첫 프레임부터 보이는 X, 패널 바깥 영역, 뒤로가기/Escape가 즉시 닫기를 제공한다. 닫기 대기 시간·확인 질문·구매 유도 재팝업을 추가하지 않는다.
2. 어두운 바깥 영역은 닫기 입력을 소비하며 뒤 로비 버튼에 입력을 전달하지 않는다. 패널 내부의 빈 영역을 누르는 행동은 구매나 닫기로 취급하지 않는다.
3. 구매 버튼에 실제 상품 조회 가격과 1회 구매임을 함께 보여준다. 3,900원은 기존 기획 가격이며 조회 실패 때 대신 보여줄 운영 가격이 아니다. 시안의 예시 가격은 시안임을 명시한다.
4. 전면·배너 제거와 판당 1회 무료 힌트의 범위를 짧게 설명한다. 가짜 할인, 카운트다운, 기간 한정, 인기 상품, 구매하지 않으면 손해라는 문구는 추가하지 않는다.
5. 구매 복구와 구매하지 않고 계속하기를 찾기 쉬운 위치에 둔다. 복구나 구매가 진행 중이면 중복 호출을 막되 홍보 패널을 닫는 동작 자체는 가능해야 한다. 플랫폼 결제창의 동작은 해당 결제창에 맡기고, 홍보 패널을 닫았다는 이유로 미결 주문을 잃지 않는다.
6. 1080×1920, 390×844, 320×568 및 짧은 호스트 안전영역에서 제목·혜택·가격·구매·닫기가 스크롤 없이 보이는지 확인한다. 주요 행동 48 CSS px, X 44 CSS px를 목표로 한다. 긴 한영 문구 때문에 가격이나 닫기가 밀리지 않아야 한다.

## 확정 광고 타이밍과 핵심 회귀 위험

아래는 최신 사용자 요구에 따른 구현 검토 기준이다. 실제 공급사의 승인이나 실광고 노출 검증을 대신하지 않는다.

- **스토리:** 정상 승리·패배·무승부마다 결과 연출이 끝난 경계에서 최대 1회 요청한다. 첫 판도 대상이며 판수·시간 유예를 추가하지 않는다. 같은 결과의 재표시·언어 변경·중복 콜백으로 재요청하지 않는다. 광고 실패를 이유로 같은 결과에서 재시도하지 않는다. 대국 중 포기·재시작은 정상 종료로 세지 않는다.
- **멀티:** 서버가 정상 결과를 확정한 방에서 사용자가 나가고 퇴장이 확인된 뒤 로비 복귀 경계에서 최대 1회 처리한다. 정상 결과를 얻은 방이라는 정보는 상태를 `idle`/`null`로 지우기 전에 보존하고, 경계 소비는 원자적으로 처리해야 한다. 앱 종료 시 광고를 띄운다는 뜻이 아니다.
- 리매치 횟수와 관계없이 같은 방에서 누적된 광고를 여러 번 표시하지 않는다. 결과 화면, 상대 리매치 요청, 요청 대기, 양측 수락, 다음 판 시작에서는 광고를 표시하지 않는다.
- 큐 취소·친구 대기 퇴장·대국 중 포기·무효 경기·연결 중단만으로 정상 완료 자격을 만들지 않는다. 상대 퇴장 뒤에도 이미 확정된 정상 결과는 유지할 수 있지만 중복 `finished`, `idle`, 퇴장 응답과 연결 종료의 경쟁으로 두 번 처리하면 안 된다. 퇴장 확인에 실패해 서버 방 상태가 불명확하면 광고는 생략하는 것을 권고한다.
- 기존 `completedMatches`, `lastInterstitialMatch`, `lastInterstitialUtc`와 구버전 광고 설정 때문에 첫 정상 종료가 빠지거나 기회가 누적되지 않는지 확인한다. 구매·진행도 저장을 초기화해 새 규칙을 적용해서는 안 된다.
- 광고가 없거나 준비되지 않았으면 다음 행동을 막지 않는다. 기존 `ResultAdBoundary`의 generation·match ID·화면 상태 검사 및 `IAdService.CancelPending()`의 지연 표시 취소 계약을 유지한다. 타임아웃, 화면 이동, 백그라운드 진입, 구매 권리 검증 성공 이후에 콜백이 와도 다음 판 위에서 표시하거나 보상을 중복 지급하면 안 된다.
- 자동 구매 홍보와 외부 전면광고를 같은 복귀 경계에 연달아 표시하지 않는다. 구매자는 전면·배너·리워드 영상을 제외하고 기존 무료 힌트 계약을 유지한다. 광고/IAP 미연동 빌드는 상품 판매·자동 홍보를 계속 숨긴다.

이전 6판/180초 안은 역사적 초안일 뿐이며, 이후 실행 검사의 기대값으로 사용하지 않는다.

## 참고 확인

- [앱인토스 IAP 공식 문서](https://developers-apps-in-toss.toss.im/documentation/common/monetization/iap/in-app-purchase): 상품 조회의 `displayAmount`는 통화를 포함한 표시 가격이다. 상품 조회·결제·미결 주문 복구를 구분한다.
- [AdMob 권장 전면광고 배치](https://support.google.com/admob/answer/6201350?hl=en): 자연스러운 콘텐츠 중단 지점과 광고 지연의 처리를 강조하며, 다음 행동 버튼을 누른 뒤 갑자기 나타나는 광고를 피하도록 안내한다. 앱인토스의 승인 완료를 뜻하지 않는다.
- [AdMob 금지 전면광고 배치](https://support.google.com/admob/answer/6201362?hl=en): 앱 시작/종료, 반복 전면 노출, 콘텐츠 조작 중 갑작스러운 표시를 구분해 설명한다. 자체 구매 홍보 패널을 SDK 전면광고와 동일 상품으로 다루지 않는다.

## 시안 검토 상태

코드·계약 사전 검토와 총괄 피드백 전달 완료. `Docs/Design/ad-removal-ui-20261018/index.html`, `preview.html`, `design-spec.md`의 독립 소스 검토를 수행했다.

- X/외부/보조 닫기/ESC, 내부 빈 곳 유지, 배경 `inert`, 포커스 순환, 예시 구매/복원에 네트워크 호출이 없는 구성을 확인했다.
- 320×403 단독 시안에서 예시 가격 안내가 숨겨지는 문제를 지적했고, 짧은 화면에서도 상단 안내가 유지되도록 보완됐다.
- 임베드 초기 로드가 상위의 비노출 상태를 받기 전 정상 재방문 패널을 잠깐 열 수 있었던 경로를 확인했다. 설계 담당자가 `embedded=1` 대기 모드를 추가했다.
- 이전 실행의 대국 완료를 추가 노출 조건으로 한 것은 첫 실제 플레이 보호를 보강한 제안이다. 단순히 두 번째 실행부터 무조건 표시하는 규칙과의 차이를 사용자 확인 시 명확히 알려야 한다.
- 선언된 불투명 색상의 정적 대비 계산: 본문 12.20:1, 구매 주의 문구 5.25:1, 보조 닫기/복원 7.67:1, 구매 버튼 5.62:1, X 8.45:1. 화면 전체의 접근성 준수 또는 실제 렌더링 검증을 의미하지 않는다.
- 검토자 CUA에는 사용 가능한 브라우저가 없어 실제 클릭 검사를 수행하지 못했다. 총괄이 별도 시안 탭에서 실제 브라우저 동작을 검증하고 캡처를 전달하면, 검토자는 해당 이미지의 배치를 독립 확인한다. 이 구분을 유지한다.

## Unity 구현 1차 독립 코드 검토

검토 대상은 `AdRemovalPurchases.cs`, `AdRemovalOffer.cs`, `AdRemovalOfferLayout.cs`, `RankMonetization.cs`, `RankGameApp.cs`, `OnlineGameController.cs`, `ProgressStore.cs`, `GameData.cs`, `AdRemovalUiBuilder.cs`, `AdOfferTests.cs`다. 코드 실행은 총괄 담당이며 검토자는 소스와 생성된 결과 파일을 읽었다.

확인한 구현:

- 저장된 `AdRemovalOffer` 프리팹을 에디터에서 만들고 루트의 직렬화 참조로 연결한다. 런타임에 UI 트리를 새로 만들지 않는다.
- 기본 `UnavailablePurchases`와 `NoFillAds`에서는 판매 홍보가 숨겨진다. 구매 완료 콜백만으로 권리를 지급하지 않고, 구매 어댑터가 제공하는 검증된 보유 상태를 별도로 확인한다.
- 표시 기회는 시작 시 한 번 소비하며, 이전 실행의 완료 기록·안정된 로비·초대/다른 화면 우선 흐름을 확인한다. 닫기를 결제 호출로 처리하지 않고 처리 대기 중에도 X/바깥/보조 닫기를 제공한다.
- 가격과 문구를 플랫폼 어댑터/Strings에서 얻으며 확정 한국어 문구가 생성 데이터에 들어 있다. X는 패널 스프라이트와 Outline 없이 별도 44×44 입력 영역을 둔다.
- 정상 멀티 완료의 `four`/`draw`만 기록하며 `left`/`timeout`/`server_pause`/`both_disconnected`는 제외한다. 리매치 화면에 광고를 띄우지 않고 퇴장 확인 후 로비 복귀 시 요청한다. 기존 스토리 해금과 멀티 완료 카운터는 분리했다.
- 기존 v1 저장에 `completedOnlineMatches`를 호환 추가하며 기존 완료/광고 이력과 구매 상태를 초기화하지 않는다. 잘못된 저장은 복구 경고와 원본 보존 경로를 유지한다.

## Unity 최종 독립 검토 결과

총괄이 저장된 프리팹을 실행하고 테스트 어댑터로 검사했다. 독립 검토자는 최종 소스, [Unity 결과 XML](../../Client/Evidence/ad-offer-implementation-20261018/unity-tests.xml), 아래 **11개 PNG 전부**를 직접 확인했다. 검토자가 Unity를 실행하거나 실제 결제/광고를 테스트한 것으로 기록하지 않는다.

**자동 검사: 40개 중 40개 통과, 실패 0개.** 첫 정상 스토리 종료부터 광고 기회 처리, 중복·늦은 콜백, 멀티 퇴장 확인, 무효 결과·리매치 중 미노출, 구매 콜백과 검증 권리 분리, 복원·취소·실패, 구매자 무료 힌트, 미연동 자동 홍보 숨김, 작은 화면의 직렬화 참조·텍스트 범위·44/48px 행동 영역을 포함한다. 실제 상품·권리 조회, 서버 구매 검증, SDK 광고 표시는 이 검사 범위에 없다.

1차 독립 지적의 해결을 소스와 회귀 검사에서 확인했다.

- `newGame`, 방 ID 변경, `idle` 전환에서 이전 완료 자격을 초기화한다. 정상 완료 방이 만료된 후 다른 방의 시간패, 정상 완료 뒤 다음 리매치의 포기는 광고 0회로 검사한다.
- 스토리·멀티 전면광고 호출의 동기 예외를 처리하고 결과 행동/로비 입력을 복구한다. 예외 어댑터 실행을 포함한다.
- `EntitlementChecked`를 구매 포트와 홍보 표시 조건에 추가했다. 상품 정보가 있어도 권리 조회가 미확정이면 홍보를 숨긴다.
- 카메라 기반 캡처의 실제 raycast 좌표를 같은 카메라로 계산하도록 검사 도우미를 보완했고, 내부 프레임 클릭이 외부 닫기로 전파되지 않는 검사가 통과했다. 1차 실행의 세 실패는 최종 결과에서 모두 해소됐다.
