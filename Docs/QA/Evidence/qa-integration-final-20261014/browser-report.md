## 확인한 흐름

1. 셰이더 수정 후 로비가 정상 표시되고 magenta 전체 화면 문제가 해소됨.
2. 대국 시작 → 플레이어 민트 착수 → AI 사고 표시·응수 확인.
3. 힌트 광고는 기본 NoFill 안내 후 입력을 계속 사용할 수 있음. 실제 SDK 광고 성공/보상 실행은 아님.
4. 쉼 → 로비, 설정, 라이선스 표시·스크롤 확인.
5. 라이선스 모달 X는 동일 브라우저/동일 빌드의 실제 중심 `(783,85)` 클릭 시 설정으로 즉시 복귀. 최초 실패 좌표 `(783,118)`은 버튼 아래로 정정됨. 이 좌표는 당시 화면에 한정한다.
6. CSS 수정 후 viewport **390×844**에서 canvas **390×693.333**, y=**75.333**으로 측정됨. 로비·7열 보드·결과 화면의 잘림 없음. 수정 전 canvas는 474.75×844로 우측 잘림이 있었음.
7. desktop **1280×720**에서는 정상 표시가 보고됐고, 최종 좁은 화면 검사 뒤 viewport override를 reset함. 최종 좁은 화면 결과와 실제 모바일 기기 검증을 구분함.
8. 스테이지 1에서 다음 수순으로 실제 승리 확인. 열 인덱스는 0부터 시작.

```text
플레이어3, AI3, 플레이어3, AI3, 플레이어1, AI1, 플레이어2, AI1, 플레이어4
전체 열 수순: 3,3,3,3,1,1,2,1,4
```

9. 총 9수에서 `연결 성공` 결과 → 로비 **2/30 해금** 확인.
10. 페이지 reload 후 **STAGE 02 / 두 돌 잇기**, **2/30 해금** 복원 확인.
11. 관찰한 콘솔 error/warning 목록은 `[]`로 보고됨.

## 판정

- QA-005: 해당 localhost WebGL 재시험에서 해소.
- QA-006: 재현 좌표 오류로 기각. 제품 수정 없이 동일 빌드에서 정상 확인.
- QA-007: 390×844 재시험에서 해소.
- 한 판의 실제 승리·진행 해금·페이지 reload 복원 흐름 확인.

이는 개발 프로토타입의 localhost 브라우저 핵심 흐름 증거다. 실제 Android/앱인토스 기기, 안전영역, 공식 테스트 광고, 네트워크/백그라운드/강제종료, 장시간 성능·저장 내구성, 사람 재미 또는 스토어 승인을 검증한 것은 아니다. 30개 승리 예시의 계산 완료 AI와 GameApp 650ms 제한의 차이는 기존 한계로 유지한다.
