## 발견한 크기 변경 결함 — QA-008 수정 확인

390→320×568로 뷰포트를 바꾸면 내용이 과소 축소됐다. 같은 320 화면을 새로고침하면 정상 크기로 복구됐다. 캔버스 DOM 크기는 정상이며 내부 UI 배치 갱신 문제로 클라이언트에 전달했다.

- `en-settings-320.jpg`: 크기 변경 직후 설정 프레임 약232px, 닫기 약36px.
- `ko-settings-320-reloaded.jpg`: 같은 뷰포트 새로고침 후 프레임 약284px, 닫기 약44px.
- 크기는 캡처 관찰값이다. 실제 터치 정확도나 기기 DPR을 측정한 값이 아니다.

수정 후 `webgl-layout-final.log`에 대응하는 WebGL 빌드를 다시 로드해 재시험했다. `SafeAreaFitter`는 CanvasScaler 갱신 이후에 크기를 계산하며 실제 가용 사각형 변경도 감지한다. 이전 캡처를 수정 후 증거로 재사용하지 않았다.

- 390×844 설정: 프레임 약346px, 닫기 약54px. `final-ko-settings-390.jpg`.
- 새로고침 없이 320×568로 변경: 프레임 약284px, 닫기 약44px. 영어 선택 정상. `final-en-settings-320.jpg`.
- 390×844로 복귀: 프레임/닫기 정상 크기, 영어·체크 표시 유지. `final-en-settings-390-resized.jpg`.
- 오른쪽 위 X 입력으로 로비 복귀 정상. 마지막에는 한국어를 선택하고 뷰포트 override를 해제했다.
- 관찰된 콘솔 error/warn은 빈 배열. `final-console.json`.

최종 크기 변경·입력 회귀는 통과다. 언어/대국 소스가 그대로인 범위에서는 앞선 전환·복원·승리 결과를 함께 사용한다. 빌드·소스 식별은 `before-resize-fix.json`과 `final-build.json`으로 구분한다. 실제 기기의 안전영역·터치·메모리/프레임은 미검증이다.
