# 상단 영역과 그래픽 브라우저 검증

2026-10-14 총괄이 로컬 WebGL 개발 빌드에 실제 포인터를 입력했다. 토스 SDK·앱·휴대폰 시험은 아니다. 상단의 `HOST PREVIEW`는 테스트용 표시이며 기본 실행에서는 숨겨진다.

## 결과

- 모의 조건: 390×844 및 320×568 CSS px, 위 inset 59·아래 34·좌우 0. 상단 예약선은 **123px(59 + 자체 여백 64)**, canvas는 viewport 전체와 일치했다. 호스트의 실제 버튼 치수 확인은 출시 전 항목이다.
- 설정에서 **390→320→390** 변경 후 크기가 정상 반영됐다. 한영 전환과 선택 유지, 닫기를 확인했다. 최종 320 화면의 일반 버튼 약47px·보드 열 약44px 판정은 Unity 렌더 좌표 검사와 함께 사용한다.
- 320 설정에서 작은 라이선스 글자 바깥의 **(52,440)**을 눌러 진입했다. 본문을 드래그해 마지막 uGUI 고지 문단까지 읽고 X로 설정에 돌아왔다.
- 390 대국에서 열 선택과 AI 응수, 320에서 첫 열의 왼쪽 가장자리 **(10,363)** 입력을 확인했다. 쉼→나가기, 도움말 열기/닫기도 정상 동작했다. 이 시험에서 새 스테이지 승리까지 검증하지는 않았다.
- 첫 검사에서 라이선스 본문이 작은 것을 확인해 24→30 논리 단위로 확대했다. **최종 빌드를 다시 로드해** 320에서 진입·확대된 본문·끝까지 스크롤·닫기, 390 복귀를 재시험했다. 같은 조건에서 본문은 약12.8px다. 일반 설정 메뉴의 작은 라벨과 클릭 영역은 유지했다.
- 관찰 구간 콘솔 오류·경고는 없었다. 재로드 후 한국어와 2/30 해금이 유지됐다. 기본 실행에서 모의 호스트 표시는 숨겨졌다.

## 증거 범위

`before-lobby-390.jpg`는 변경 전 화면이다. `ko-*`, `en-*`는 새 상단/그래픽 기능 검사이며 라이선스 본문 확대 전 빌드다. `final-*`는 본문 확대 후 최종 빌드의 재검사다. 기능 검사와 최종 본문 재검사를 구분하며 전체를 한 번의 같은 빌드 시험으로 표현하지 않는다. 최종 Unity 렌더 검사는 한영·7화면·390→320→390을 별도로 포함한다.
