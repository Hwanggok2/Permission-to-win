# Tabletop UI — 사용자가 거부한 이전 시안

**최신 상태(2026-10-14): 사용자가 크림/청록 디자인을 거부했다.** 이 문서는 당시 설계·자산·검사 증거의 보존 기록이며 최종 수용/출시 디자인이 아니다. 현재 방향은 [흰 바탕·검정 격자·흑백 돌과 계급 카드](RANK-UI-DIRECTION.md)다. 아래 두 결과 버튼 제한은 폐기됐고 승리 ‘다음’이 복구된다. 이전 증거의 완료 여부와 새 디자인의 수용 여부를 구분한다.

2026-10-14 (KST). **새 PNG21개 생성·저장 테마/프리팹 연결과 픽셀 검사, 제공 Unity 캡처의 표본 시각 검토 완료. Unity 최종59/59 뒤 소스 동결, 개발 빌드 해시 확인 완료. 최종 브라우저 판정은 진행 중**. 앞선 SoftUI와 단계 지도 작업은 색상·배치·기능 정리였다. 이를 이번 그래픽 리뉴얼 완료로 표현하지 않는다. 기존 Unity/브라우저 통과도 당시 빌드의 기능 증거이며 새 아트의 통과가 아니다.

## 당시 Tabletop 방향 — 현재 대체됨

| 역할 | 색/표현 |
| --- | --- |
| 바탕 | 밝은 크림 `#F5F2E9` |
| 글자·외곽·보드 구조 | 짙은 청록 `#173E43` |
| 플레이어 말 | 민트 `#67D6B0` + **링** 표식 |

| 공통 형태 | 같은 얇은 외곽선, 짧은 하단 그림자, 라운드. 패널·버튼·보드 테두리는 9-slice, 빈칸은 안으로 들어간 구멍 표현 |

아이콘은 같은 선과 크기 기준으로 구성한다. 쉼/나/AI 같은 반복 텍스트에 의존하던 표현을 자체 도형 아이콘과 말 표식으로 정리하되, 실제 행동과 플레이어/AI 구분이 읽혀야 한다. 필요한 언어 문구는 기존 Excel/Client **137개 한영 문자열** 계약을 유지한다. 새 이미지·글꼴·외부 아이콘 세트나 참고 화면의 종이·손글씨·해칭을 복사하지 않는다.

원본 기하 도형을 만드는 Editor 생성 도구를 확장하고 결과는 `Client/Assets/StageGame/Art/TabletopUI/`에 저장한다. 기존 `SoftUI/`·사용자 자산은 보존한다. 실제 화면·공통 버튼·보드·말은 저장 프리팹과 직렬화 참조로 연결한다. 파일 생성이나 색상 코드 변경만으로 화면 적용을 선언하지 않는다.

로비는 5×2 단계 지도·선택 정보·시작 행동을 간결하게 정리하고 중력/4목 도움말을 유지한다. 데이터137·진행 저장·광고 경계·라이선스 전문은 유지한다. [호스트 예약과 44px 입력 조건](HOST-UI.md)을 함께 검증하며 그림자·외곽선이 버튼/호스트 영역을 침범하지 않게 한다.

## 당시 결과 UX — 최신 요청에서 다음 버튼 복구

- 플레이어 또는 AI가 승리한 마지막 말을 **1.45→1.0 배율로 약400ms** 동안 놓고, **승리 줄을 약500ms** 더 보여준다. 승부 처리 시작부터 보드·힌트·일시정지 입력을 막고 연출 뒤 광고 기회를 처리한 후 결과 버튼을 활성화한다. 양측 승리에 같은 연출을 적용하며 무승부에는 승리 말 애니메이션이나 승리 줄을 만들지 않는다.
- 모든 결과에서 **다시 도전 / 로비로** 두 버튼만 가로로 배치한다. 큰 결과 패널·보드를 덮는 차폐·다음 단계·별도 닫기 버튼은 제거하고 보드와 승리 줄을 유지한다. 승리 강조는 말의 원래 색/표식을 남기고 금색 테두리를 더하는 방향이다. 기존 3버튼/다음 강조 화면의 통과는 이번 구조의 증거가 아니다.
- 승리 해금과 완료 저장은 유지한다. 로비로 돌아가면 다음 해금 단계를 선택하며, 마지막30 완료 뒤31을 만들지 않는다. 재도전은 방금 플레이한 단계를 다시 시작한다. 새 문구 추가 없이 기존137개 한영 문자열을 사용한다.
- 버튼이 보드/안전영역을 침범하지 않는지, 연출 중 입력과 중복 결과가 차단되는지, 재도전/로비 전환 뒤 확대 말·승리 줄·이전 결과 버튼이 남지 않는지 확인한다. 광고 실패가 진행을 막지 않는 기존 결과 경계도 유지한다. 시간·시각 효과의 실제 편안함은 사람/기기 검사 전 미검증이다.

| 대비/가독성 | 작은 상태 글자, 비활성/선택 노드, 크림 위 민트·산호의 경계, 라이선스 긴 본문. 팔레트 자체 계산상 청록/크림은 약10.38:1, 청록/민트6.54:1, 청록/산호4.85:1인 반면 크림/민트1.59:1·크림/산호2.14:1이므로 색면만으로 경계를 맡기지 않는다. 이는 지정 색의 계산이며 최종 합성 화면·접근성 인증 결과가 아니다. |

**검증 순서:** 생성 코드/파일·SHA-256 → 저장 프리팹 참조 → 새 아트의 ko/en 320×568·390×844 캡처 → 총괄의 해당 빌드 브라우저 입력/스크롤/크기 변경. 브라우저는 graphics-after 빌드까지 보류하며 실제 휴대폰 검증은 **0기기**다. 단계 UX/브라우저 이력은 [QA](../QA/STAGE-UX-RESULTS.md)와 [총괄 증거](../Management/Evidence/reference-ux-browser-20261014/README.md)에 연결하되, 새 아트 증거를 이전 결과와 구분한다.
