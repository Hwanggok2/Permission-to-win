# 멀티 최종 수·승패·레이팅 연출

2026-10-19 KST. 사용자 추가 요청에 대한 **구현용 설계1안과 총괄의 최종 적용 결정**이다. [간단한 결과 배치 시안](index.html). 이 역할은 디자인 문서만 작성했고 코드·Excel·Unity 프리팹·실제 게임을 수정하거나 실행하지 않았다. 아래 최종값은 총괄의 구현 보고를 기록한 것이며 실제 검증 증거와 구분한다.

## 결론

**기존 화면을 그대로 유지하고, `Game/Turn`을 큰 승패 제목으로, `Footer/Result`를 레이팅 숫자로 전환한다.** 중앙 보드와 별도 상태 안내, 같은 줄의 다시하기/나가기는 그대로 남긴다. 결과 모달이나 추가 전체 스크롤은 만들지 않는다.

기존 `OnlinePanelLayout`은 footer의 실제 텍스트 높이를 먼저 확보한 뒤 나머지 공간에 정사각형 보드를 맞춘다. 이 구조를 재사용하면 큰 승패와 숫자를 넣어도 버튼이 화면 아래로 밀리지 않는다. 종료된 판은 착수 입력이 없으므로403px 높이에서는 보드 축소를 허용한다.

## 최종 적용 결정

2026-10-19 총괄 구현 보고: 큰`Turn` 승패 제목, 하단 레이팅 구획, 고정된 다시하기/나가기 두 버튼을 적용했다. 승리한 연결을 보여 주는 **금색 승리선**과 **최종 수 링**도 추가했다. 다음 값이 아래 초기 시퀀스 표보다 우선한다.

| 최종 돌 확대 | 0.20초,1.00→**1.65배** |
| 확대 상태 유지 | 0.10초 |

초기1.4배/340ms보다 확대폭을 키우고 짧은 정지 구간을 두어 작은 화면에서도 마지막 수를 알아보기 쉽게 했다. 금색 선·링이 최종 승리 형태와 마지막 돌 위치를 보조한다. 하단 행동은 연출 시작부터 제공하므로 결과 확인을 기다리지 않고 다음 행동을 선택할 수 있다.

이 결정은 기존 **상대 마지막 돌의 흰 테두리**와 별개인 종료 강조다. 게임 중 내가 착수하면 흰 강조를 숨기는 규칙은 유지한다. 금색 강조·점수 카운트 역시 새 판/방 전환/나가기에서 정리하고 서버 결과를 바꾸지 않는다. 돌을 특정할 수 없는 종료는 새 최종 돌을 추측하지 않는 원칙을 유지한다.

아래 치수는 초기 배치 목표로 보존한다. 실제 프리팹의 최종 수치·작은 화면 통과 여부는 총괄의 최신 측정/캡처를 따른다. HTML 모형은 최신0.65초/1.65배/0.55초와 즉시 사용 가능한 두 버튼으로 갱신했다.

## 저장된 구성과 치수

`OnlinePanel.prefab`의 기존 `Title/CloseButton`, `Game/Mine`, `Opponent`, `First`, `Turn`, `Board`, `Footer/Result`, `Notice`, `Rematch`, `Leave`를 재사용한다. 필요한 경우 에디터에서만 `Footer/RatingDelta` 라벨을 추가해 저장·직렬화한다. 런타임에 UI 트리를 만들지 않는다.

1080×1920 물리 픽셀은 DPR3 표본360×640 CSS로 함께 검토한다. Unity 저장 좌표는 프로젝트의1080 단위와 `RankUiMetrics.U` 변환을 따르며 위 CSS 수치를 직렬화 값에 그대로 대입하지 않는다. 긴 영문/오류가2–3행이면 기존 `preferredHeight` 방식으로 footer만 위로 확장하고 보드를 줄인다. 버튼은 계속 하단 고정이다. **403px보다 작은 실제 가용 영역의 통과 여부는 별도 측정한다.**

승패 제목은 별도 이미지 없이 Pretendard 굵은 글자와 기존 카키·크림 색으로 표시한다. 승리/패배의 뜻은 글자로 전달하고 색만으로 구분하지 않는다. 변화량은`+16`/`−16`처럼 부호를 반드시 붙인다. 점수가 바뀌지 않으면0을 중립 색으로 표시한다.

## 초기 전환 시퀀스 — 최종 적용값은 위 절 우선

아래340ms/1.4배/다시하기 지연 활성화는 최초 설계 이력이다. **최종 구현은 위의0.65초/1.65배와 즉시 활성화로 바뀌었다.**

| 시각 | 동작 | 입력 |
| --- | --- | --- |
| 0ms | 서버의 새 종료 상태 수신. 현재 판을 확정하고 마지막 돌 확대 시작 | 보드 착수 금지. 닫기·나가기는 사용 가능 |
| 0–120ms | **최종 돌1개**를1.00→1.40배 확대 | 보드 전체·footer 위치는 고정 |
| 120–340ms | 같은 돌을1.40→1.00배로 부드럽게 복원 | 마지막 착수 위치를 유지 |
| 약340ms | 큰 승패 제목을 표시하고 레이팅 숫자 변화 시작 | 다시하기 활성화. 나가기는 계속 사용 가능 |
| 340–890ms | `최종 점수−서버 delta`에서 최종 점수까지550ms 정수 카운트 | 사용자가 재대결/나가기를 누르면 남은 연출을 취소 |
| 890ms 이후 | 최종 점수와 증감량을 고정 | 요청/상대 퇴장 안내는 별도 Notice에서 갱신 |

총 약0.9초이며 반복 점멸·화면 흔들기·폭죽·전체 화면 확대는 추가하지 않는다. 숫자는 ease-out으로 목표에 단조롭게 접근하며 최종값을 지나치지 않는다. 표시만 애니메이션하고 실제 레이팅·계급은 서버 확정값을 유지한다. 최종 점수가100/200/300 경계를 지날 때 거짓 계급을 중간 숫자로 판정하지 않는다.

`OnlinePanelLayout.Fit()`은 매번 `board.localScale`을 다시 계산하므로 **Board 전체 transform을 줌 연출에 쓰면 안 된다.** 저장된 최종 `stones[index].rectTransform.localScale`만 조절한다. 마지막 상대 돌의 흰 테두리 규칙은 변경하지 않는다. 내 마지막 돌에 강제로 상대 수 흰 테두리를 붙이지 않는다.

## 마지막 수와 중복 처리

- `lastOpponentMove`는 상대의 마지막 수이므로 **내가 끝낸 판의 최종 수를 알아내는 값으로 쓰면 안 된다.** 같은 roomId·round의 직전 playing 보드와 새 finished 보드를 비교해 새로 채워진 한 칸을 식별한다.
- 정상4목/42칸 무승부가 새 착수로 끝난 경우 그 돌을 확대한다. 시간 초과·퇴장·무효 등 새 돌이 없는 종료는 돌 확대 없이 승패·레이팅 표시 단계로 간다.
- roomId + round별 새 finished 전이에 한 번만 실행한다. 서버 반복 상태, 상대 리매치 요청, 상대 퇴장, 연결 상태 갱신 때문에 다시 재생하지 않는다.
- 재접속 후 이미 끝난 판을 처음 받은 경우에는 이전 수를 추정해 확대하지 않는다. 최종 승패·점수를 즉시 보여 준다.
- 새 판, 방 이동, 패널 비활성화, 나가기, 연출 중 리매치 시작 시 코루틴과 숫자 카운트를 중단하고 확대된 돌의 스케일을1로 복원한다. 이전 판 연출이 새 판의 돌에 남으면 안 된다.
- 레이팅 OFF 또는 실제delta0에서는 숫자를 억지로 변화시키지 않는다. 현재 점수와 변동 없음 안내를 정적으로 보여 준다. 무승부라도 서버 delta가0이 아니면 서버값대로 카운트한다.

## 결과 행동

- **기본:** 카키 주 행동`다시하기`, 크림 보조 행동`나가기`를 현재 위치에 유지한다. 버튼을 아래로 세로 쌓지 않는다.
- **내가 요청:** 버튼에는 짧은`요청 보냄`/`Requested`를 비활성 표시하고 Notice에 기존`상대방 응답 대기 중`을 유지한다. 같은 긴 문구를 버튼과 Notice에 두 번 쓰지 않는다.
- **상대 요청:** Notice에 기존 요청 문구, 다시하기는 바로 수락할 수 있는 주 행동. 큰 승패와 레이팅은 유지한다.
- **상대가 나감:** 다시하기는 비활성, 나가기를 카키 주 행동으로 전환한다. 기존 구현과 동일하다.
- **연결 끊김:** 결과·점수를 지우지 않고 Notice만 바꾼다. 연결이 없으면 다시하기 비활성, 나가기는 계속 가능하다.
- 나가기에는 추가 결과 확인창을 만들지 않는다. 진행 중 나가기의 기존 패배 확인창은 그대로 유지한다. 멀티 광고는 결과 연출이나 리매치 요청에 삽입하지 않고, 기존 사용자 확정대로 방을 떠나 로비로 돌아갈 때 최대1회 처리한다.

## 문구·데이터

기존 `result_win`, `result_draw`, `mp_rematch`, `mp_leave`, `mp_rematch_request`, `mp_rematch_wait`, `mp_opponent_left`를 재사용한다. `result_loss`는 현재“다시 도전해 보세요”이므로 큰 패배 제목으로 쓰지 않는다.

최소 추가 키 후보는 `mp_outcome_loss`(패배 / You lose), `mp_rating_transition`(레이팅{0} → {1} / Rating {0} → {1}), `mp_rating_unchanged`(레이팅 변동 없음 / Rating unchanged), `mp_rematch_sent`(요청 보냄 / Requested)다. 증감 부호는 기존 숫자 포맷을 재사용한다. 최종 키·한영은 Excel Strings 원본에서 관리하며 이 디자인 역할은 수정하지 않는다.

## 확인 항목

1. 내가 놓은 승리 수·상대가 놓은 패배 수·무승부 최종 수가 각각 올바른 한 돌만 확대하는지 확인한다.
2. 중복 finished·재접속·상대 요청·퇴장으로 연출이 반복되지 않는지 확인한다.
3. 200→216,216→200,OFF200→200,무승부 유효 증감,0점 하한을 포함해 끝 숫자가 서버값과 일치하는지 확인한다.
4.320×403 한영에서 승패·레이팅·Notice·48px 두 행동이 보드와 겹치거나 잘리지 않는지 확인한다. 390×844·1080×1920도 비교한다.
5. 연출 중 나가기·첫 프레임 재대결 수신·패널 숨김에서 돌 스케일과 이전 점수가 새 판에 남지 않는지 확인한다.

HTML은 저장 UI 구성의 배치·짧은 전환을 설명하는 모형이다. 실제 게임 입력·서버·Unity 레이아웃 검증 증거로 사용하지 않는다. 기존 아트와 폰트는 읽기 전용으로 참조하며 새 외부 자산은 추가하지 않는다.
