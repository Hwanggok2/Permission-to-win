# 멀티 UI 리모델링 배치안

2026-10-18 KST · 설계/독립 검토 반영 초안. [전체 와이어프레임](index.html). 설계 담당은 `Docs/Design/`만 수정했고 Unity 실행·최종 제품 검증은 하지 않았다. 기존 도트 군대 분위기, 목재 보드, Pretendard와 테마 패널을 유지한다. SVG 도형 보드는 배치 설명이며 교체할 게임 자산이 아니다.

## 원인과 선택

현재 `OnlinePanel`은 게임 전체를 `ScrollRect` 안에 넣고 내용 높이 1220 + 헤더 120 + 위아래 최소 여백 64를 사용한다. 720×1280 설계 화면보다 124가 커서 결과·다시하기·나가기가 화면 밑으로 밀린다. 마지막 결과 라벨이 리매치/퇴장 메시지로 대체되어 승패·점수도 사라진다.

새 구조는 헤더 / 양측 프로필 / 선공·돌 / 차례 / 가변 정사각형 보드 / 결과·알림 / 하단 행동이다. **게임 화면과 핵심 메뉴는 스크롤하지 않는다.** 가용 영역이 작으면 중앙 판만 작아지고 주요 버튼은 고정된다. 결과와 상대 상태는 별도 라벨로 항상 함께 표시한다.

## 기본 치수

프리팹에서 쓰는 논리 단위 720×1280을 기준으로 한다. 실제 저장 좌표는 `RankUiMetrics.U()`에 따라 1.5배인 1080×1920이다. `SafeAreaFitter`가 실제 OS/호스트 영역을 제외한 내부 크기를 전달하며, 멀티 배치는 그 가용 영역만 사용한다.

| 영역 | 일반 높이 / 논리 단위 | 720×1280 SVG 위치 | 규칙 |
| --- | ---: | --- | --- |
| 헤더 | 96 | y0–96 | 제목 좌측, 닫기 우측. 닫기 입력은 44 CSS px 이상 |
| 양측 프로필 | 112 | y108–220 | 나/상대 두 칸. 돌 아이콘, 계급, 점수. 긴 영어 계급은 줄바꿈 |
| 선공·내 돌 | 36 | y224–260 | 별도 라벨, `mp_you_first/other_first`와 `mp_black/white` 재사용 |
| 차례·시간 | 64 | y260–324 | 독립 고대비 띠. 끝나면 대국 종료. 정보 의미를 색에만 의존하지 않음 |
| 정사각형 보드 | 최대 672 | x24, y340, 672×672 | 가용 높이에 따라 축소. 원래 정사각형과 가로/세로 격자 비율 보존 |
| 결과 + 상대 상태 + 버튼 | 220 | y1060–1280 | 하단 고정. 결과/점수 1행 + 상대 상태 1행 + 행동 108 + 아래20 |
| 다시하기 / 나가기 | 108 | y1152–1260 | 각328, 간격16. 같은 줄에 항상 표시 |

여백은 총24 이상과 하단16 이상을 목표로 하되 실제 가용 높이와 글자 높이 기준으로 계산한다. SVG는 치수 이해용 정지 표본이며 레이아웃 식의 런타임 증거가 아니다. 높이가 남을 때 보드를 세로로 늘리거나 footer를 아래로 밀지 않는다.

### 짧은 화면

사용 가능한 CSS 높이가600 미만이면 고정 영역을 CSS 크기로 계산한다. 320×568에 호스트가 상하157px를 차지하고 추가 위8px가 있으면 가용403px인 극단 표본이 된다.

| 영역 | 압축 CSS 높이 |
| --- | ---: |
| 헤더 | 44 |
| 프로필 | 40 |
| 선공·돌 | 16 |
| 차례 | 28 |
| 고정 하단 | 92: 결과22 + 상대 상태18 + 간격4 + 행동48 |
| 영역 간격 합계 | 8 |
| 남는 판 영역 | 175 (403 − 228) |

이92px 하단은 짧은 결과·리매치 문구의 기본값이다. **실제 결과와 상태 라벨의 `preferredHeight`가 더 크면 2–3행을 배정하고, 버튼의 하단 좌표·48px 높이를 유지한 채 footer를 위로 확장한다.** 판이 남는 공간에 맞춰 추가 축소한다. 영어 `mp_connection_lost`처럼 긴 연결 안내를1행에 자르거나 글자를 계속 줄이는 방식은 허용하지 않는다. 종료·연결 실패처럼 착수할 수 없는 상태의 작은 판에는 활성 보드 입력24px 기준을 적용할 필요가 없다. 진행 중에도 판 최소 폭을 지키기 어려운 경우는 기준 미달로 별도 보고하고 숨기지 않는다.

주요 행동은 48 CSS px, 닫기는 44 CSS px 이상이다. 일반96 논리 단위 닫기 높이를320px 폭에 그대로 비례 축소하면42.7px이므로, **실제44px 최소치로 보정**해야 한다. 175px 판의7열 선택 폭은25px 수준이다. 별도1–7 번호 스트립은 시선 이동·추가 높이·규칙 오해 비용 때문에 추가하지 않는다. 기존 열 선택 후 `놓기` 확정 흐름을 유지하며, 작은 판의 선택 미리보기를 확인할 수 있어야 한다. 7열을 동시에44px 이상으로 만들면서 판·모든 텍스트·48px 행동을403px 높이에 넣는 것은 불가능하므로 보드 공간적 선택과 핵심 행동을 구분한다. 이 절충은 실제 입력 검증이 필요하다.

압축 표본의11–12px 보조 글자는 가용403px 극단에만 한정한다. 호스트 영역이 없는 일반320×568에서는13–14px 이상의 정보 텍스트를 권장한다. 기본 글자 크기를 낮추는 방식으로 모든 화면을 압축하지 않는다.

영역이 더 줄어드는 가로 창은 가로 안전 공간과 부모의 실제 가용 폭/높이를 먼저 적용한다. 이 초안은 화면 회전으로 새로운 가로 게임 화면을 추가하지 않는다. 기존 세로 캔버스를 유지할 때 작은 높이에서도 행동이 잘리지 않는지 별도 측정하고, 기준 미달을 통과로 기록하지 않는다.

기존 Excel 키를 재사용한다. `mp_players` 단일 라벨을 나/상대 각각으로 분리하려면 역할·계급·점수 조합용 키를 Excel에 등록해야 한다. SVG의 `내 계급`, `상대 찾는 중` 같은 설명용 임시 문구를 제품 코드에 복사하지 않는다. 제품은 `mp_profile`, `mp_searching` 등을 사용한다. 새 사용자 문구는 Excel Strings 한/영 원본에서만 관리한다.

`mp_result_win/loss/draw`는 승패·변화·현재점수를 유지한다. 기존 문구를 무리하게 축소하지 말고 최소 두 줄 여유를 검토한다. 영어 `Sergeant First Class`, `Lieutenant General`, `Waiting for opponent`, `Your opponent requested a rematch`, `Join with these settings`를 스트레스 표본으로 쓴다.

## 프리팹·구현 경계

- 저장된 `OnlinePanel.prefab`의 Header / Menu / Game / Footer / LeaveConfirm과 직렬화된 참조를 사용한다. 런타임 UI 트리 생성 금지.
- 반응형 fitter는 저장된 RectTransform의 크기/위치만 계산한다. 전체 화면의 콘텐츠 높이를 키우거나 ScrollRect로 문제를 숨기지 않는다.
- 보드/Stone/Column/Preview/LastOpponentMove 원본 자산 및 입력 동작을 보존한다. 상대 마지막 돌의 흰 강조는 내가 확정 착수하면 숨기는 최신 규칙을 유지한다.
- 결과 라벨과 알림 라벨을 분리한다. 알림 발생 시 하단 버튼 위치를 유지하고 필요한 경우 footer만 위로 확장한다. 연결 복구 안내도 기존 결과를 지우지 않는다. 진행 중 `otherDisconnected`처럼 긴 상태 문구와 보드 입력이 함께 살아 있는 경우에는 활성 열의24px 폭을 실제 측정해 별도 판정한다.
- 레이팅/선공/친선전 옵션의 서버 계약은 변경하지 않는다. 실제 공유 방식·게스트 인증·과금 설정 변경도 이번 설계에 포함하지 않는다.

## 독립 검토와 검증 기준

총괄 구현 담당과 별도 UI 검토 담당이 배치를 검토했다. 1차 피드백으로 결과/상대상태 분리, 하단 고정, 작은 화면의 주요48px 행동, 긴 영어 문구, 번호 스트립 제외를 반영했다. 2차 소스·좌표 검토로 긴 오류 안내의 footer 위 확장, 닫기의44px 최소치, 일반 화면의 정보13–14px와 극단 표본11–12px 구분을 추가했다. 실제 프리팹/브라우저 검증은 이후 별도 증거를 남겨야 한다.

- 1080×1920, 390×844, 320×568, 320×568 호스트 표본과 가로 안전 공간에 대해 한국어/영어 전체 상태를 캡처한다.
- 두 행동 버튼과 닫기/취소가 안전 영역에 완전히 들어오며, 스크롤 없이 입력 가능한지 확인한다.
- 결과/요청/퇴장/재접속의 연속 상태 전환에서도 승패·점수와 행동 위치를 유지한다.
- 가장 긴 계급 및 문구를 실제 폰트로 측정하고 잘림, 겹침, 최소 글자 크기, 클릭 영역을 확인한다.
- 무작위매칭/초대/ON·OFF/착수/리매치/퇴장은 실제 WebSocket과 브라우저에서 확인하되 UI 개편으로 서버 동작 변경이 없음을 검증한다.

## 공식 참고 자료

### 구현 후 보정

Unity Pretendard 실제 높이 검사와 독립 캡처 검토를 거쳐 압축 프로필은44px, 극단적으로 짧은 화면의 선공16px·차례26px로 조정했다. 하단은 결과22px·상태18px를 최소값으로 삼고 실제 글자 높이에 따라 위로 확장한다. 차례는 기존 화면에 맞춰 큰 텍스트로 강조하며 SVG의 녹색 띠는 쓰지 않는다. 상대 퇴장 후 대기 문구를 해제하고 나가기를 강조하며, 퇴장 확인은 취소가 주 행동이다. [최종 검증과 실제 화면](../../../Client/Evidence/multiplayer-ui-20261018/README.md)을 와이어프레임보다 우선한다.

확인일: 2026-10-18 KST. 참고 서비스의 자산/레이아웃을 복제하지 않고 행동 순서와 접근성 기준을 적용한다.
