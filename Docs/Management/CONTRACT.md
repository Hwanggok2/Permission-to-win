# MVP 확정 계약 v5

갱신: 2026-10-14 총괄. 사용자 제공 참고 화면에서 진행 상태·행동 우선순위·그림 설명 원칙을 분석하고 단계 선택과 도움말 개선을 확정했다. 참고 게임의 그래픽 표현과 콘텐츠는 복제하지 않는다. IAP/서버는 구현 예정이며 현재 개발판에는 없다. 한눈에 보는 최신 결정은 `Overview/index.html`, 변경 기록은 `Overview/CHANGES.md`에 둔다.

## 게임

- 내부 작업명 StageGame. 상점용 이름은 권리 확인 후 확정한다.
- 7열 × 6행 중력식 4목. 열을 눌러 가장 낮은 빈 칸에 돌을 놓는다. 가로/세로/대각선으로 4개 이상 연결하면 승리. 합법 수 없는 가득 찬 판은 무승부.
- 플레이어=1, AI=-1, 빈 칸=0. 열 인덱스 0~6. 턴 교대, 가득 찬 열 불가. 승리/무승부 후 추가 착수 금지.
- 오프라인 AI 싱글플레이, 30개 초기 스테이지(3챕터 × 10). 첫 구현은 1판→결과→다음 스테이지 루프까지.
- 자유 오목/렌주/물리 알까기/온라인 대전/자체 회원가입/랭킹/구독/재화 판매는 MVP 범위 밖. 플랫폼 사용자 확인은 구매 검증에 필요한 최소 범위로 적용한다.
- 중간 국면은 시작측부터 합법적으로 재생 가능한 열 순서로 표현한다. 재생 중 이미 종료되는 배치 금지. 불가능/떠 있는 돌 배열 금지.
- AI는 깊이/노드 예산/실수 비율로 난이도 변화. 즉시 승리/즉시 패배 방어 우선, 임의 난수로 치팅하지 않는다. 깊이/시간은 실측 후 조정.
- 판당 45~120초는 목표이고 측정 전 보장하지 않는다. 손실 원인 표시/전술 국면은 차별화 가설.

## 프로젝트와 UI

- Unity 6000.3.15f1, 프로젝트 루트 `Client/`. 설치된 Android 및 WebGL 모듈 활용.
- 세로 화면에서 720×960 논리 콘텐츠를 가용 영역에 배치한다. 기존 720×1280보다 세로 간격을 줄여 토스 상단 여백을 확보하고 작은 화면의 입력 크기를 유지한다. 자체 단순 도형·민트/산호 돌·짙은 배경을 공통으로 사용한다. 돌 표식으로 색 외 구분도 제공한다. 폰트 재배포 권리 검증.
- 화면마다 핵심 행동 하나를 강조하고 닫기 위치를 통일한다. 일반 화면에서 SDK 연결 상태·광고 자리 채움용 개발 문구는 숨긴다. 작은 화면의 가독성/입력 영역과 영어 줄바꿈은 실제 렌더로 검증하며 사람/실기기 사용성은 별도로 평가한다.
- 설정에서 한국어·영어 선택, 즉시 화면 갱신, 기기 내 언어 저장·다음 실행 복원을 제공한다. 모든 일반 UI 문구와 스테이지 이름은 Excel Strings 키로 참조한다. 법적 원문·개발 로그·데이터 로드 실패 최소 안내는 예외다.
- 씬 `Client/Assets/StageGame/Scenes/Main.unity`. 공통 CloseButton/PrimaryButton, 로비, 보드, 결과, 설정·도움말 모달을 저장된 프리팹으로 제작한다.
- 최초 생성 에디터 도구 허용. 이미 생성된 사용자 프리팹을 재생성/덮어쓰지 않는다. 런타임 UI 트리 조립 금지.

### 호스트 상단 영역과 그래픽

- 토스 실행 시 모든 게임 화면·팝업의 버튼과 본문은 호스트 상단 조작 영역 아래에 둔다. 배경·캔버스는 전체 화면을 채우며 호스트의 닫기·더보기·뒤로가기를 가리지 않는다.
- 토스 공식 문서는 X 버튼의 상단 위치를 safe inset + 5(iOS) / + 10(Android)으로 안내하지만 전체 버튼 높이는 명시하지 않는다. 별도로 **64 CSS px를 예약하는 것은 StageGame의 보수적 설계값**이다. 공식 높이 또는 실기기 확인값으로 표기하지 않는다. [공식 Safe Area](https://developers-apps-in-toss.toss.im/documentation/common/screen/safe-area), 확인 2026-10-14.
- WebGL은 호스트/기기 inset과 추가 예약 영역을 구분한다. 같은 inset을 CSS와 Unity 양쪽에서 중복 공제하지 않으며, CSS 좌표와 실제 캔버스 픽셀 비율을 변환한다. Android 단독 앱에는 토스 전용 여백을 적용하지 않는다. SDK 연결 전 모의 입력과 실제 토스 검증을 구분한다.
- 320px 폭·짧은 화면에서도 게임 버튼·닫기·라이선스 진입의 터치 영역은 44 CSS px 이상을 목표로 검사한다. 크기 변경·언어 변경·모달·노치/홈 영역을 함께 검증한다. 세로 화면 지원이며 가로 모드의 사용성은 별도 확인 대상이다.
- 검증한 최소 가용 조건은 세로 viewport 320×568, 위 inset 59·아래34 이하, 좌우0이다. 일반 버튼110 논리단위(약47px), 보드 열720/7(약44px)를 확보한다. 더 작은 가용 영역까지 동일한 터치 크기를 보장하지 않는다. 라이선스 본문30 논리단위(최소 조건에서 약12.8px), 진입 라벨26과535×110 터치 영역을 사용한다.
- 패널·버튼·보드는 같은 둥근 모서리와 짙은 색 계열, 돌은 민트/산호와 기존 표식으로 통일한다. 외부 그래픽을 추가하지 않고 직접 생성한 단순 도형을 저장된 스프라이트·프리팹으로 사용한다. 생성 코드·출처·파일 해시는 자산 대장에 기록한다.
- 설정 하단의 라이선스 진입은 작은 보조 텍스트로 표시하되 터치 영역을 줄이지 않는다. 별도 스크롤 화면에서 폰트·라이브러리의 필요한 저작권 및 라이선스 전문을 읽을 수 있어야 한다. 추가 외부 자산을 도입한다면 상업 이용·수정·앱 내 배포·고지 조건을 공식 원문으로 먼저 확인한다.

### 참고 화면에서 반영할 사용자 경험

- 로비는 챕터별 10개 단계(5열×2행)를 보여주고 챕터를 넘겨 30개를 탐색한다. 선택 단계 이름·진행 상태와 큰 시작 버튼을 가까이 배치한다. 모든 단계를 한 화면에 축소하거나 목록과 고정 버튼을 겹치지 않는다.
- 완료·현재 도전·잠금을 짧은 글자/기호와 색으로 구분하고 선택 표시는 별도로 둔다. 잠긴 단계를 살펴보는 것은 허용하되 플레이는 차단하고 먼저 완료할 단계를 안내한다. 완료 단계는 다시 도전할 수 있다.
- 1~10 입문, 11~20 전술, 21~30 도전은 챕터 표시 이름이다. 실제 사람에게 검증된 난이도 등급으로 주장하지 않는다.
- 진행은 최고 완료 단계도 저장해 30단계의 완료와 단순 해금을 구분한다. 기존 저장은 해금 단계 - 1까지만 완료로 추론하며 마지막 단계 완료를 추측하지 않는다. 언어·효과음·광고 카운터·중복 결과 방지는 유지한다.
- 도움말은 저장된 도형과 짧은 문구로 열 선택→아래 빈칸, 가로·세로·대각선 4개 연결을 설명한다. 글자만 긴 설명과 그림의 잘린 캡션을 피한다. 새 문구는 Excel 한국어/영어로 관리한다.
- 승리 결과의 주요 행동은 다음 단계, 패배·무승부는 재도전이다. 로비 이동은 보조 행동으로 구분한다. 기존 광고 처리 경계와 입력 차단을 유지한다.
- 기존 자체 도형·폰트·민트/산호 색 체계를 활용한다. 참고 이미지·종이 질감·손글씨 로고·학교 직책·해칭 그림자는 게임과 홍보물에 복사하지 않는다. 별도 랭킹·PvP·기간제 구매를 추가하지 않는다.
- 저장/잠금/완료/언어 회귀, 프리팹 참조, 작은 화면의 44px 입력과 캡션을 검사한다. 스크린샷 분석 및 자동 검증으로 재미나 사용자 친화성을 입증했다고 하지 않는다. 사람에게 첫 도전 찾기·규칙 설명·재도전을 관찰한다.

## 데이터 교환

- Excel 원본/메타행 관례는 `GameData/FORMAT.md`를 따른다. 데이터 담당은 원본→검증→JSON exporter를 제공한다.
- 생성 위치 `GameData/Generated/stages.json`, `ads.json`, `strings.json`.
- 클라이언트 담당이 읽고 자신의 `Assets/StageGame/Resources/GameData/`에 복사/임포트한다. 데이터 담당이 Client/에 쓰지 않는다.
- JSON은 Unity JsonUtility 호환 wrapper object 사용. 필드 이름은 아래처럼 고정. 문자열 UTF-8.

```json
{"schemaVersion":1,"stages":[{"id":1,"chapter":1,"titleKey":"stage_001","aiDepth":1,"aiNodeBudget":1000,"aiRandomPermille":250,"starter":1,"openingMoves":""}]}
```

- `id`: 1~30 고유 정수; `chapter`: 1~3; `titleKey`: strings에 존재; `aiDepth`: 1~6; `aiNodeBudget`: 100~30000; `aiRandomPermille`: 0~1000; `starter`: 1 또는 -1; `openingMoves`: 쉼표로 구분된 0~6 열 인덱스 또는 빈 문자열.
- runtime validation 실패 시 명확한 오류와 안전한 로비 복귀. 잘못된 데이터를 정상 데이터처럼 무시하지 않는다.

```json
{"schemaVersion":1,"interstitialGraceMatches":3,"interstitialEveryMatches":2,"interstitialCooldownSeconds":90,"bannerLobby":true,"bannerResult":true,"rewardedHintsPerMatch":1}
```

```json
{"schemaVersion":1,"strings":[{"key":"stage_001","ko":"첫 수","en":"First Move"}]}
```

- 기존 schemaVersion/key/ko를 유지하고 en을 추가한다. Excel `Content_Kor`/`Content_Eng`를 사용하며 양 언어의 필수 번역·중복 키·숫자 포맷 인자를 내보내기 전에 검증한다. 세부 규칙은 `GameData/LOCALIZATION-CONTRACT.md`를 따른다.

## 광고와 진행

- 첫 3판 전면광고 제외. 이후 최소 2판 및 90초를 모두 충족하는 대국 종료 경계에서만 시험. 결과 행동 버튼 활성화 전 광고 기회를 처리해 다음 판 중 늦게 표시되는 일이 없어야 한다.
- 배너: 로비/결과 예약 공간만. 대국/일시정지/앱 재진입에서는 전면광고 금지.
- 리워드: 자발적 선택 힌트 1회/판. 미준비/취소/실패면 무보상. 성공 1회만 지급. 무제한 무료 재도전을 광고 시청으로 막지 않는다.
- 실제 광고 SDK/계정 ID가 없으면 로컬 테스트 어댑터를 명시하며 수익 연동 완료로 보고하지 않는다.
- 첫 프로토타입은 광고 준비 안 됨(no fill)을 기본으로 하고 Editor에서만 모의 완료/실패/중복 테스트 가능.
- 진행도 최고 해금 및 최고 완료 스테이지를 로컬 저장. 게임 데이터와 저장 버전 분리. 기존 저장은 보존하며 새 완료 필드를 호환 추가한다. 동일 결과/보상 중복 처리 방지.

## 광고 제거 구매와 서버

- 상품은 1회 구매 광고 제거 1종. 가격 기획안 3,900원이며 플랫폼에서 지원하는 실제 가격·정산 조건을 확인해 판매 가격을 확정한다. UI 가격은 플랫폼 상품 조회값을 쓴다.
- 구매자는 전면·배너·리워드 영상을 모두 보지 않는다. 힌트는 광고 없이 1회/판 제공하고 AI·스테이지·무료 재도전 조건은 동일하게 유지한다.
- 로비/설정에 저장된 구매·구매 복구 프리팹을 추가한다. 성공 팝업만으로 권리를 주지 않고 서버 검증이 끝난 뒤 광고를 취소/제거한다. 검증 대기는 중복 구매로 해결하지 않는다.
- 권리와 복구는 구매한 플랫폼 계정 기준. 원스토어와 토스 간 구매 공유는 MVP에서 제공하지 않는다. 게임 진행도 클라우드 동기화와 구매 복구를 구분한다.
- 서버 방향: Cloudflare Workers Free(TypeScript) + D1 Free + Workers Secrets/mTLS binding. 이전 Cloud Run·월 3만원 관리안은 사용자 무료 조건으로 폐기한다. 구매/사용자 검증, 주문별 1회 처리, 권리 조회·복구·환불 반영만 담당한다. 대국·AI·Excel 데이터·진행도는 기기에 둔다. 실제 배포·인증서·토스 mTLS 호환은 미검증이다.
- 무료 플랜 한도 안에서 서버비 0원 운영을 목표로 하고 유료 전환을 하지 않는다. 한도/장애 시 새 구매를 중지하고 미처리 주문은 복구 가능하게 남긴다. 기존 검증 권한과 오프라인 플레이는 유지한다. 광고/IAP 플랫폼 수수료는 별개다. 실제 계정의 무료 플랜·mTLS 접근·CPU/쿼리 한도 검증 후 서버 채택을 운영 확정한다.
- 원스토어는 관리형 비소모성 방식으로 소비하지 않고 구매 확인(acknowledge)을 한다. 토스는 현재 공식 IAP의 상품 유형·복구 정책을 확인해 연결한다. 외부 일반 결제로 디지털 상품 IAP를 우회하지 않는다.
- 마지막으로 검증한 유효 구매 권리는 통신 실패만으로 회수하지 않는다. 재연결 시 재검증하고 확인된 환불/취소를 반영한다. 처음 구매·새 기기 복구에는 연결이 필요하다. 클라이언트 플래그만을 서버 권리의 근거로 삼지 않는다.
- 원스토어 첫 버전이 무광고라면 광고 제거를 판매하지 않는다. 광고 연동과 제거 효익이 실제로 제공되는 버전에서만 활성화한다. 토스 수익화 버전에는 광고와 광고 제거를 함께 검증한다.
- 결제/복구/환불/중복/서버 장애/플랫폼 계정 변경 검증을 기존 테스트와 별도 출시 조건으로 추가한다. 상세 기술 범위는 `Server/README.md`, 정책 근거는 `Docs/Design/RELEASE-REQUIREMENTS.md`를 따른다.

## 이번 구현 완료 증거

- 실제 저장된 Scene/Prefab과 플레이 가능한 규칙/AI/진행 코드.
- 규칙/AI/데이터/광고 상태 테스트 결과. Unity 컴파일 및 가능하면 EditMode 테스트 증거.
- Android/WebGL 산출물은 실제 빌드 성공 때만 완료 표기. 광고 승인/스토어 승인/실기기 검증은 각각 별도 상태.
