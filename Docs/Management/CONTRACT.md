- 이야기는 별도 긴 화면 없이 AI 말풍선으로 전달한다. 첫 대사는 기존 22자 제한보다 사용자 원문을 우선하고, 한국어·영어 모두 읽을 수 있는 1~2줄을 허용한다. Excel Strings가 원본이며 `aiIntroKey`/`aiWinKey`/`aiLoseKey`로 연결한다. `aiWinKey`는 AI 승리, 즉 플레이어 패배 대사다.
- 7열 × 6행 중력식 4목. 열을 눌러 가장 낮은 빈칸을 미리 보고 ‘놓기’로 확정한다. 교차점 모양의 흰 격자판을 사용해도 자유 오목으로 바꾸지 않는다. 가로/세로/대각선으로 4개 이상 연결하면 승리. 합법 수 없는 가득 찬 판은 무승부.
- 플레이어=1, AI=-1, 빈 칸=0. 열 인덱스 0~6. 턴 교대, 가득 찬 열 불가. 승리/무승부 후 추가 착수 금지.
- 오프라인 AI 싱글플레이, 30개 초기 스테이지. UI는 10계급 × 각 3단계로 표시한다. 기존 chapter 필드는 데이터 호환을 위해 유지한다.
- 자유 오목/렌주/물리 알까기/온라인 대전/자체 회원가입/랭킹/구독/재화 판매는 MVP 범위 밖. 플랫폼 사용자 확인은 구매 검증에 필요한 최소 범위로 적용한다.
- 중간 국면은 시작측부터 합법적으로 재생 가능한 열 순서로 표현한다. 재생 중 이미 종료되는 배치 금지. 불가능/떠 있는 돌 배열 금지.
- AI는 깊이/노드 예산/실수 비율로 난이도 변화. 즉시 승리/즉시 패배 방어 우선, 임의 난수로 치팅하지 않는다. 깊이/시간은 실측 후 조정.
- 판당 45~120초는 목표이고 측정 전 보장하지 않는다. 손실 원인 표시/전술 국면은 차별화 가설.

### 호스트 상단 영역과 그래픽

- 토스 실행 시 모든 게임 화면·팝업의 버튼과 본문은 호스트 상단 조작 영역 아래에 둔다. 배경·캔버스는 전체 화면을 채우며 호스트의 닫기·더보기·뒤로가기를 가리지 않는다.
- 토스 공식 문서는 X 버튼의 상단 위치를 safe inset + 5(iOS) / + 10(Android)으로 안내하지만 전체 버튼 높이는 명시하지 않는다. 별도로 **64 CSS px를 예약하는 것은 StageGame의 보수적 설계값**이다. 공식 높이 또는 실기기 확인값으로 표기하지 않는다. [공식 Safe Area](https://developers-apps-in-toss.toss.im/documentation/common/screen/safe-area), 확인 2026-10-14.
- WebGL은 호스트/기기 inset과 추가 예약 영역을 구분한다. 같은 inset을 CSS와 Unity 양쪽에서 중복 공제하지 않으며, CSS 좌표와 실제 캔버스 픽셀 비율을 변환한다. Android 단독 앱에는 토스 전용 여백을 적용하지 않는다. SDK 연결 전 모의 입력과 실제 토스 검증을 구분한다.
- 320px 폭·짧은 화면에서도 게임 버튼·닫기·라이선스 진입의 터치 영역은 44 CSS px 이상을 목표로 검사한다. 크기 변경·언어 변경·모달·노치/홈 영역을 함께 검증한다. 세로 화면 지원이며 가로 모드의 사용성은 별도 확인 대상이다.
- 검증한 최소 가용 조건은 세로 viewport 320×568, 위 inset 59·아래34 이하, 좌우0이다. 일반 버튼110 논리단위(약47px), 보드 열720/7(약44px)를 확보한다. 더 작은 가용 영역까지 동일한 터치 크기를 보장하지 않는다. 라이선스 본문30 논리단위(최소 조건에서 약12.8px), 진입 라벨26과535×110 터치 영역을 사용한다.
- 그래픽 기준은 흰색 바탕과 보드, 검정 계열의 격자·본문·외곽선, 흑백 돌이다. 별점과 선택/승리 표시는 제한된 강조색 또는 선으로 구분한다. 청록 보드 구멍·민트 고리/산호 마름모는 활성 화면에서 교체한다. 과한 장식과 반복 정보는 줄인다.
- 판의 외곽은 정사각형이고 내부 격자의 가로/세로 간격은 동일하다. 7열×6행 규칙을 보존하므로 교차점 사이 영역은 6×5 정사각형 칸이며 바깥 여백으로 판 외곽의 가로/세로 크기를 맞춘다. 비활성 가짜 행이나 추가 착수점을 만들지 않는다. 검정선 굵기는 일관되게 렌더하며 축소 시 선이 사라지지 않아야 한다. 상세 미리보기에도 같은 비율을 적용한다.
- 정사각형 판과 상단 정보·44px 이상 버튼을 동시에 담을 수 없는 짧은 화면에서는 세로 스크롤 등으로 내용 접근을 보존한다. 전체를 축소해 입력 영역을 줄이는 방식으로 해결하지 않는다. 실제 지원 최소 화면에서 스크롤/고정 영역/모달/승리 연출을 재검증한다.
- 공통 닫기/일시정지/도움말/설정/삼각 이동/잠금/완료 아이콘과 간단한 원형 AI 얼굴을 자체 도형으로 제작한다. 로비·대국·결과·설정·도움말·확인·라이선스에 같은 룩을 적용한다. 외부 그래픽 추가 없이 저장된 스프라이트·프리팹을 사용하고 생성 코드·출처·해시를 자산 대장에 기록한다. 이전 자산은 보존한다.
- 그래픽 완료 판정에는 실제 빌드의 전후 화면 비교와 작은 화면·한영·모달·대국 확인이 필요하다. 소스/프리팹 검사만으로 시각 품질을 완료 처리하지 않는다. 사용자 취향과 사람의 이해도는 자동 검사로 확정하지 않는다.
- 설정 하단의 라이선스 진입은 작은 보조 텍스트로 표시하되 터치 영역을 줄이지 않는다. 별도 스크롤 화면에서 폰트·라이브러리의 필요한 저작권 및 라이선스 전문을 읽을 수 있어야 한다. 추가 외부 자산을 도입한다면 상업 이용·수정·앱 내 배포·고지 조건을 공식 원문으로 먼저 확인한다.

### 참고 화면에서 반영할 사용자 경험

- 로비는 중앙 큰 제목 아래 큰 2열 단계 카드를 세로 스크롤한다. 30개를 한 화면에 축소하지 않는다. 카드는 계급·단계번호·별점·상태만 표시하고, 하단 ‘대국 시작’은 멀티플레이 전용 **준비 중**으로 표시한다. 온라인 매칭/서버 기능을 구현한 것처럼 보이지 않게 한다.
- 카드 선택 시 오른쪽에서 상세 패널이 슬라이드한다. 실제 openingMoves를 재생한 시작판, 계급/별점, 간략한 설명 한 줄, 좌우 삼각 이동, 우상단 X, 하단 시작하기를 저장된 프리팹 참조로 구성한다. 모달 아래 카드 입력은 막고 닫을 때 목록 스크롤 위치를 보존한다. 마지막/첫 단계에서 범위를 넘지 않는다.
- 완료·현재 도전·잠금을 짧은 글자/기호와 색으로 구분하고 선택 표시는 별도로 둔다. 잠긴 단계를 살펴보는 것은 허용하되 플레이는 차단하고 먼저 완료할 단계를 안내한다. 완료 단계는 다시 도전할 수 있다.
- 계급은 각 3단계씩 훈련병·이등병·일병·상병·병장·하사·중사·상사·소위·중위다. 각 6단계마다 별 1~5개를 표시한다. 계급/별은 기획상 구간이며 사람에게 검증된 난이도 등급으로 주장하지 않는다.
- 진행은 최고 완료 단계도 저장해 30단계의 완료와 단순 해금을 구분한다. 기존 저장은 해금 단계 - 1까지만 완료로 추론하며 마지막 단계 완료를 추측하지 않는다. 언어·효과음·광고 카운터·중복 결과 방지는 유지한다.
- 신규 첫 실행은 로비 선택 없이 첫 단계를 시작하고 짧은 착수 안내를 표시한다. 기존 저장의 진행도·언어·완료 기록을 보존하며 기존 이용자를 신규로 취급하지 않는다. 첫 실행 여부는 저장해 이후 로비로 진입한다.
- 제목 아래에는 모자를 쓴 원형 AI 얼굴·계급·별점을 한 줄로 묶어 전체 그룹을 가운데 정렬한다. 계급별 모자는 자체 단순 도형이며 실제 군 문장이나 참고 게임 자산을 복사하지 않는다. 그 아래 말풍선을 두고, 기존 상시 ‘내 차례’ 행은 없앤다. 계급별 시작/AI 승리/AI 패배 대사를 Excel 한국어/영어로 관리한다. 모욕적이거나 긴 문구를 피한다.
- 플레이어 차례 시작에 화면 중앙의 큰 ‘내 차례 / Your turn’ 표시가 잠깐 나타났다가 사라진다. 저장된 프리팹과 직렬화 참조를 사용하고 포인터 입력을 가로막지 않는다. AI 응수·새 판·되돌리기에 따른 실제 차례 전환과 연결하며 언어 갱신/힌트로 중복 재생하지 않는다. 모달·결과·새 판에서 이전 팝업이 뒤늦게 남지 않도록 정리한다. 플레이어 얼굴은 표시하지 않는다.
- 하단 세 버튼은 **되돌리기 / 놓기 / 다시하기**다. 놓기는 원형, 양옆 버튼은 간단한 형태와 같은 선/글자 기준을 사용한다. 선택한 열의 가장 낮은 빈칸에 반투명 미리보기만 표시하며 ‘놓기’를 누를 때 1회 착수한다. 가득 찬 열을 선택하면 이전 미리보기를 지우고 놓기를 비활성화한다. AI 차례·가득 찬 열·종료 상태에서 잘못 착수하지 않는다. 도움말도 열 선택→미리보기→놓기와 4개 연결을 설명한다.
- 되돌리기는 대국 중 무료로 직전 플레이어 수와 이어진 AI 응수를 함께 취소한다. AI 응수 전에는 내 수 하나를 취소한다. 초기 openingMoves 이전으로 돌아가지 않는다. AI 계산 중 취소한 수의 응수가 늦게 반영되지 않아야 한다. 미리보기·턴·승패를 함께 복구하고 완료/광고 통계를 중복 기록하지 않는다. 종료 연출/결과에서는 되돌리기를 허용하지 않는다. 재도전은 같은 초기 국면으로 돌아간다.
- 로비 이동/다시하기는 대국 중·일시정지·결과 모두 저장된 공통 확인 패널을 거친다. ‘나가시겠습니까?’/‘다시하시겠습니까?’와 취소·해당 행동 버튼을 표시한다. 취소는 보드·미리보기·수순·진행을 보존하고 원래 화면으로 돌아온다. 수락은 1회만 실행하며 중복 클릭/늦은 AI·광고 콜백을 막는다. 이미 결과가 저장된 판은 안내 문구가 완료 기록 삭제를 암시하지 않아야 한다. 다음 단계·착수·단순 패널 닫기에 불필요한 재확인을 추가하지 않는다.
- 승리 결과에 **다음 단계**를 복구한다. 마지막 30단계에는 존재하지 않는 다음 단계를 만들지 않는다. 다시 도전/로비로도 접근할 수 있으며 패배·무승부는 두 버튼을 가로 배치한다. 큰 패널·보드 차폐·별도 결과 닫기는 사용하지 않는다. 승리 줄과 마지막 말을 계속 볼 수 있어야 한다.
- 플레이어와 AI 모두 승부를 낸 마지막 말은 약 1.45배에서 원래 크기로 놓이는 약 0.4초 애니메이션을 보여준다. 이어 약 0.5초 승리 줄을 볼 시간을 준다. 승부 처리 시작부터 보드·힌트·되돌리기·놓기·재도전·일시정지 입력을 막고, 연출이 끝난 뒤 광고 기회를 처리하고 해당 결과 버튼을 활성화한다. 같은 결과의 저장/광고/보상을 두 번 실행하지 않는다. 무승부에는 승리 말 애니메이션을 붙이지 않는다.
- 재도전은 같은 스테이지를 다시 시작한다. 승리 해금/완료 저장은 보존하며 로비로 돌아오면 최고 해금 단계가 선택돼 다음 도전을 시작할 수 있다. 마지막 단계 후 31단계를 만들지 않는다. 버튼과 연출 대상은 저장된 프리팹의 직렬화 참조를 사용한다.
- 기존 자체 도형·폰트와 새 자체 흑백 도형을 활용한다. 참고 이미지·종이 질감·손글씨 로고·학교 직책·해칭 그림자는 게임과 홍보물에 복사하지 않는다. 별도 랭킹·실제 PvP·기간제 구매를 추가하지 않는다.
- 저장/잠금/완료/언어 회귀, 프리팹 참조, 작은 화면의 44px 입력과 캡션을 검사한다. 스크린샷 분석 및 자동 검증으로 재미나 사용자 친화성을 입증했다고 하지 않는다. 사람에게 첫 도전 찾기·규칙 설명·재도전을 관찰한다.

## 데이터 교환

- Excel 원본/메타행 관례는 `GameData/FORMAT.md`를 따른다. 데이터 담당은 원본→검증→JSON exporter를 제공한다.
- 생성 위치 `GameData/Generated/stages.json`, `ads.json`, `strings.json`.
- 클라이언트 담당이 읽고 자신의 `Assets/StageGame/Resources/GameData/`에 복사/임포트한다. 데이터 담당이 Client/에 쓰지 않는다.
- JSON은 Unity JsonUtility 호환 wrapper object 사용. 필드 이름은 아래처럼 고정. 문자열 UTF-8.

```json
{"schemaVersion":1,"stages":[{"id":1,"chapter":1,"titleKey":"stage_001","aiDepth":1,"aiNodeBudget":1000,"aiRandomPermille":250,"starter":1,"openingMoves":""}]}
```

- `id`: 1~30 고유 정수; `chapter`: 1~3; `titleKey`: strings에 존재; `aiDepth`: 1~6; `aiNodeBudget`: 100~30000; `aiRandomPermille`: 0~1000; `starter`: 1 또는 -1; `openingMoves`: 쉼표로 구분된 0~6 열 인덱스 또는 빈 문자열.
- runtime validation 실패 시 명확한 오류와 안전한 로비 복귀. 잘못된 데이터를 정상 데이터처럼 무시하지 않는다.

- v8의 Stage 추가 필드: `rankKey`, `descriptionKey`, `difficultyStars`(1~5), `aiIntroKey`, `aiWinKey`, `aiLoseKey`. 문자열 키는 한국어/영어 데이터에 존재해야 한다. `aiWinKey`는 AI가 승리했을 때의 대사이며 플레이어 패배에 사용한다. `titleKey`는 계급+계급 내 단계명으로 바꾼다. 기존 30개 초기 국면과 AI 설정은 이번 UI 변경에서 보존한다. 추가 필드와 검증의 정확한 내보내기 형식은 GameData/FORMAT.md와 일치시킨다.

```json
{"schemaVersion":1,"interstitialGraceMatches":0,"interstitialEveryMatches":1,"interstitialCooldownSeconds":0,"bannerLobby":true,"bannerResult":true,"rewardedHintsPerMatch":1}
```

```json
{"schemaVersion":1,"strings":[{"key":"stage_001","ko":"첫 수","en":"First Move"}]}
```

- 기존 schemaVersion/key/ko를 유지하고 en을 추가한다. Excel `Content_Kor`/`Content_Eng`를 사용하며 양 언어의 필수 번역·중복 키·숫자 포맷 인자를 내보내기 전에 검증한다. 세부 규칙은 `GameData/LOCALIZATION-CONTRACT.md`를 따른다.

## 광고와 진행

- 2026-10-18 사용자 확정: 스토리 정상 승리·패배·무승부마다 완료 ID당 최대 1회 전면광고 기회를 처리한다. 첫 판수 유예·시간 쿨다운은 없다. 결과 행동 버튼 활성화 전 처리하며 중도 포기·재시작은 제외한다. 멀티는 정상 `four`/`draw` 종료 후 서버 퇴장 확인을 받은 로비 복귀에서 최대 1회다. 리매치·검색/친구 대기·시간패·무효·연결 중단·퇴장 확인 실패는 제외하고 여러 판의 광고를 누적하지 않는다.
- 배너: 로비/결과 예약 공간만. 대국/일시정지/앱 재진입에서는 전면광고 금지.
- 리워드: 자발적 선택 힌트 1회/판. 미준비/취소/실패면 무보상. 성공 1회만 지급. 무제한 무료 재도전을 광고 시청으로 막지 않는다.
- 실제 광고 SDK/계정 ID가 없으면 로컬 테스트 어댑터를 명시하며 수익 연동 완료로 보고하지 않는다. 광고 어댑터 오류·미충전·취소·기한 초과는 진행을 막지 않으며 화면 이동/백그라운드/검증된 구매 이후 늦은 콜백을 무효화한다.
- 광고 제거 홍보는 이전 실행에서 스토리 또는 멀티 대국을 완료한 이용자에게 새 게임 실행의 안전한 로비에서 한 번만 검사한다. 도움말·초대·다른 화면 진입이 우선하며 미룬 홍보를 뒤늦게 띄우지 않는다. 새 WebGL 인스턴스를 만드는 페이지 새로고침은 새 실행이고 같은 인스턴스의 로비 재방문·백그라운드 복귀는 새 실행이 아니다.
- 실광고 지원과 상품 준비·표시 가격·권리 확인 완료·미보유가 모두 확인되어야 자동 홍보를 표시한다. `NoFillAds`/`UnavailablePurchases` 기본값에서는 자동 홍보를 숨기되, 로비 광고 제거 버튼으로 준비중 안내를 직접 열 수 있다. 이때 구매·복원은 비활성화한다. X/바깥 터치/보조 닫기로 즉시 닫으며 처리 대기 중에도 닫을 수 있다. 구매 콜백만으로 권리를 지급하지 않고 검증된 보유 상태를 확인한다. 보유자는 광고 없이 싱글 힌트 판당 1회를 사용한다.
- 첫 프로토타입은 광고 준비 안 됨(no fill)을 기본으로 하고 Editor에서만 모의 완료/실패/중복 테스트 가능.
- 진행도 최고 해금 및 최고 완료 스테이지를 로컬 저장. 게임 데이터와 저장 버전 분리. 기존 저장은 보존하며 새 완료 필드를 호환 추가한다. 동일 결과/보상 중복 처리 방지.

## 광고 제거 구매와 서버

- 상품은 1회 구매 광고 제거 1종. 가격 기획안 3,900원이며 플랫폼에서 지원하는 실제 가격·정산 조건을 확인해 판매 가격을 확정한다. UI 가격은 플랫폼 상품 조회값을 쓴다.
- 구매자는 전면·배너·리워드 영상을 모두 보지 않는다. 힌트는 광고 없이 1회/판 제공하고 AI·스테이지·무료 재도전 조건은 동일하게 유지한다.
- 로비/설정에 저장된 구매·구매 복구 프리팹을 추가한다. 성공 팝업만으로 권리를 주지 않고 서버 검증이 끝난 뒤 광고를 취소/제거한다. 검증 대기는 중복 구매로 해결하지 않는다.
- 권리와 복구는 구매한 플랫폼 계정 기준. 원스토어와 토스 간 구매 공유는 MVP에서 제공하지 않는다. 게임 진행도 클라우드 동기화와 구매 복구를 구분한다.
- 서버 방향: Cloudflare Workers Free(TypeScript) + D1 Free + Workers Secrets/mTLS binding. 이전 Cloud Run·월 3만원 관리안은 사용자 무료 조건으로 폐기한다. 구매/사용자 검증, 주문별 1회 처리, 권리 조회·복구·환불 반영만 담당한다. 대국·AI·Excel 데이터·진행도는 기기에 둔다. 실제 배포·인증서·토스 mTLS 호환은 미검증이다.
- 무료 플랜 한도 안에서 서버비 0원 운영을 목표로 하고 유료 전환을 하지 않는다. 한도/장애 시 새 구매를 중지하고 미처리 주문은 복구 가능하게 남긴다. 기존 검증 권한과 오프라인 플레이는 유지한다. 광고/IAP 플랫폼 수수료는 별개다. 실제 계정의 무료 플랜·mTLS 접근·CPU/쿼리 한도 검증 후 서버 채택을 운영 확정한다.
- 원스토어는 관리형 비소모성 방식으로 소비하지 않고 구매 확인(acknowledge)을 한다. 토스는 현재 공식 IAP의 상품 유형·복구 정책을 확인해 연결한다. 외부 일반 결제로 디지털 상품 IAP를 우회하지 않는다.
- 마지막으로 검증한 유효 구매 권리는 통신 실패만으로 회수하지 않는다. 재연결 시 재검증하고 확인된 환불/취소를 반영한다. 처음 구매·새 기기 복구에는 연결이 필요하다. 클라이언트 플래그만을 서버 권리의 근거로 삼지 않는다.
- 원스토어 첫 버전이 무광고라면 광고 제거를 판매하지 않는다. 광고 연동과 제거 효익이 실제로 제공되는 버전에서만 활성화한다. 토스 수익화 버전에는 광고와 광고 제거를 함께 검증한다.
- 결제/복구/환불/중복/서버 장애/플랫폼 계정 변경 검증을 기존 테스트와 별도 출시 조건으로 추가한다. 상세 기술 범위는 `Server/README.md`, 정책 근거는 `Docs/Design/RELEASE-REQUIREMENTS.md`를 따른다.

## 이번 구현 완료 증거

- 실제 저장된 Scene/Prefab과 플레이 가능한 규칙/AI/진행 코드.
- 규칙/AI/데이터/광고 상태 테스트 결과. Unity 컴파일 및 가능하면 EditMode 테스트 증거.
- Android/WebGL 산출물은 실제 빌드 성공 때만 완료 표기. 광고 승인/스토어 승인/실기기 검증은 각각 별도 상태.
