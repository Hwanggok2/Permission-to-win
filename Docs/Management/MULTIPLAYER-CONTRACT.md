## 사용자 흐름

- 로비 하단 **멀티 배틀** → 무작위 매치 / 친선전. 저장된 `OnlinePanel.prefab`과 직렬화된 참조를 사용한다.
- 무작위 매치는 항상 레이팅을 반영한다. 검색을 취소할 수 있고 180초 안에 상대가 없으면 대기열에서 나온다. 가짜 상대나 AI로 대체하지 않는다.
- 친선전은 방장이 **레이팅 반영 ON/OFF**를 선택한다. 기본 ON. 초대받은 친구에게 입장 전 실제 설정을 표시하고 서버가 입장 시 다시 확인한다. 설정이 바뀌면 입장을 거절하고 최신 설정을 다시 보여 준다. 시작 후 변경할 수 없으며 리매치에도 유지한다.
- 공유 버튼은 Web Share / Android 공유 시트를 연다. 카카오톡을 포함한 설치 앱 선택은 OS와 브라우저 지원에 따른다. 별도 Kakao SDK·앱 키는 추가하지 않았다. URL 복사 버튼과 복사 실패 시 직접 선택할 주소도 제공한다.
- 초대 주소는 `https://hwanggok2.github.io/Permission-to-win/#invite=<32자리 난수>` 형식이다. 초대는 10분 후 만료된다. 초대 링크로 게임에 들어오면 레이팅 설정을 확인하고 입장한다. Android 앱 링크 연결은 별도 설정하지 않았으므로 현재 공유 대상은 웹 주소다.
- 서버가 낮은 레이팅의 플레이어에게 선공을 준다. 같은 점수면 난수로 결정한다. 선공과 내 돌 색을 별도로 표시한다. 첫 참가자는 흑, 두 번째 참가자는 백이며 흑이 항상 선공인 것은 아니다.
- 결과에서 **다시하기 / 나가기**를 제공한다. 양쪽이 다시하기를 눌러야 새 판을 시작한다. 한쪽 요청 시 상대에게 “상대방이 리매치를 요청하였습니다”, 퇴장 시 “상대방이 나갔습니다”를 표시한다. 퇴장한 상대와 혼자 리매치할 수 없다.
- 진행 중 나가기는 패배 처리 안내 후 확인한다. 결과 화면의 나가기는 로비로 바로 돌아간다.

## 점수·계급

모든 새 게스트는 **200점**으로 시작한다. 점수는 싱글플레이 스테이지 AI의 표시 레이팅과 별개다. 기대 승률 `E = 1 / (1 + 10^((상대점수 - 내점수) / 400))`, 변화량 `32 × (결과 - E)`를 사용한다. 결과는 승리1/무승부0.5/패배0. 양·음 대칭으로 반올림하고 승패에는 최소1점을 적용한다. 최저점0 때문에 이전할 점수가 부족하면 양쪽 변화량을 함께 제한한다. 정산은 서버가 판당 한 번만 처리한다.

| 내 점수 / 상대 | 이기면 | 지면 |
| --- | ---: | ---: |
| 200 / 200 | +16 | −16 |
| 200 / 400 | +24 | −8 |
| 400 / 200 | +8 | −24 |

친선전 OFF는 승패·시간 초과·퇴장·리매치 모두 점수와 레이팅 대국 횟수를 바꾸지 않는다. ON과 무작위 매치는 같은 공식이다. 점수가 다른 둘의 무승부는 기대 승률에 따라 점수가 이동할 수 있다. 이 수치들은 최초 운영안이며 실제 유저 분포에서 공정성·대기시간이 검증된 값은 아니다.

| 점수 시작 | 계급 | 점수 시작 | 계급 |
| ---: | --- | ---: | --- |
| 0 (100 포함) | 훈련병 | 1100 | 소위 |
| 200 | 이등병 | 1200 | 중위 |
| 300 | 일병 | 1300 | 대위 |
| 400 | 상병 | 1400 | 소령 |
| 500 | 병장 | 1500 | 중령 |
| 600 | 하사 | 1600 | 대령 |
| 700 | 중사 | 1700 | 준장 |
| 800 | 상사 | 1800 | 소장 |
| 900 | 원사 | 1900 | 중장 |
| 1000 | 준위 | 2000 이상 | 대장 |

각 계급은 다음 경계 직전까지 유지한다. 100점 미만도 훈련병이며 2000점 이상은 대장 표시를 유지하되 점수 상한은 없다.

## 매칭·접속·서버

오래 기다린 사람을 우선 처리하고 허용 범위 안에서 가장 가까운 레이팅의 상대를 찾는다. 동률이면 먼저 기다린 후보를 고른다. 허용 격차는 ±100으로 시작해 15초마다 100씩 넓혀 최대400이다. **두 사람 모두의 현재 대기 범위**에 들어야 매칭한다. 레이팅과 대기 시간만 사용하며 지역·네트워크 지연 측정은 이번 준비에 포함하지 않았다.

별도 Cloudflare Workers + SQLite Durable Object에서 7×6 중력식 규칙, 착수 순서, 열 범위/포화, 판 번호·착수 순번, 결과, 레이팅을 결정한다. 클라이언트가 보낸 점수·승패는 받지 않는다. WebSocket Hibernation과 자동 ping/pong을 사용한다. 저장 데이터는 게스트 식별자·레이팅·접속/대기/대국 상태이며 초대 토큰이나 인증 비밀을 URL/로그에 넣지 않는다. 초대 토큰은 URL fragment에만 포함된다.

256비트 게스트 비밀을 첫 접속 응답으로 발급하고 클라이언트 기기에 저장한다. 서버는 비밀의 SHA-256 매핑을 보관한다. 같은 게스트의 새 연결은 이전 연결을 종료한다. 기기 저장소 삭제·다른 브라우저·다른 기기에서는 별도 게스트가 되며 계정 복구/기기 간 공유는 제공하지 않는다. 기기 토큰 탈취 방어와 다계정·친선전 점수 주고받기 방지는 공개 경쟁 서비스 수준으로 검증하지 않았다.

| 설정 | 현재 값 |
| --- | ---: |
| 한 차례 제한 | 60초 |
| 재접속 유예 | 45초 |
| 초대 유효 시간 | 600초 |
| 매칭 대기 만료 | 180초 |
| 결과 방 유지 | 300초 |
| 차례 마감 후 서버 지연 무효 기준 | 120초 |

시간 초과는 패배, 한쪽 연결 종료 후 유예 만료는 퇴장 패배다. 양쪽 모두 유예가 만료되면 점수 없이 방을 정리한다. 서버 처리 자체가 차례 마감보다120초 넘게 늦으면 점수 없이 무효 처리한다. 알람 주기는10초이므로 무입력 만료 처리는 최대 약10초 늦을 수 있으나 마감 이후 들어오는 착수는 서버 시각으로 거절한다.

무료 구성을 유지하며 별도 결제/구매 서버의 예산과 분리해서 확인한다. 코드에는 소켓200개, 방200개, 전체 게스트1만명, 새 게스트100명/시간의 보수적 제한을 둔다. 이는 무료 사용량 보장이 아니다. 현재 구조는 한 Durable Object에서 상태를 순회하므로 대규모 부하와 실제 무료 소진 장애는 미검증이다. 공식 Free 한도가 소진되면 멀티 접속/착수가 실패할 수 있으며 로컬 AI 플레이는 계속 가능하다. 유료 전환이나 초과 과금을 전제로 하지 않는다.

## 데이터·대사·시각 표시

`GameData_MVP.xlsx`의 Multiplayer 시트가 시작점수·Elo·검색·시간 설정 16개의 원본이다. exporter가 `multiplayer.json`을 생성하고 서버가 import한다. Strings의 총489개 ko/en 키에 멀티 문구와 계급을 포함한다. 클라이언트에 사용자 문구를 별도로 하드코딩하지 않는다.

2026-10-18 UI 리모델링: 멀티 메뉴·초대·대국·결과 전체 스크롤을 제거하고 실제 안전영역에 맞춘 저장 프리팹을 사용한다. 결과·점수와 상대 상태는 별도 라벨이며, 다시하기/나가기는 같은 하단 줄에 고정한다. 긴 안내는 위로 확장하고 판이 남은 공간에 맞춰 줄어든다. 주요 행동48 CSS px·닫기44px, 활성 판 열24px를 검사한다. 좁은 호스트 표본에서는 판이 약175px로 작아지는 절충이 있다. 설계/독립 검토/구현을 나눠 진행했고 Unity5/5·142개 화면·데이터47/47을 확인했다. [배치와 근거](../Design/multiplayer-ui-20261018/layout-spec.md) · [검증 및 공개 상태](../../Client/Evidence/multiplayer-ui-20261018/README.md).

상대의 마지막 돌은 흰 픽셀 테두리로 표시하고 **플레이어가 돌을 놓으면 즉시 숨긴다**(2026-10-18 사용자 변경). 열 선택만으로는 숨기지 않고, 상대가 다시 두면 그 돌에 표시한다. 온라인은 착수 전송 대기 중에도 숨기며 서버가 착수를 거절하면 복원한다. 선공·돌 색과 무관하게 실제 착수 순서를 따른다. 사전 배치된 시작 돌에는 표시하지 않는다. AI 되돌리기는 복원된 판의 마지막 착수에 맞춰 표시하며 새 판·상대 변경 시 초기화한다.

2~30단계 시작/AI 승리/AI 패배 문구를 검토해 대국 전에는 도전·소문·재대결, 결과에는 승패에 대한 반응을 말하도록 바꿨다. 예: 하사 시작은 “프로라고 들었다. 어디 실력 좀 볼까?”다. 첫 훈련병의 지정 문구는 유지한다. 24단계 대회 안내와 병사부6라운드도 유지한다. [현재 대사표](../Design/CHARACTERS.md).

## 근거와 검증 경계

공식 자료 확인일: 2026-10-18. [Chess.com Elo 설명](https://www.chess.com/terms/elo-rating-chess)의 상대 점수에 따른 기대 결과를 참고했다. Chess.com의 실제 [Glicko 안내](https://support.chess.com/en/articles/8566476-how-do-ratings-work-on-chess-com)와 [Lichess Glicko-2](https://lichess.org/page/rating-systems)는 불확실성을 포함하는 다른 방식이다. 이 게임은 사용자에게 변화량을 설명하기 쉬운 고정K Elo를 선택했으며 해당 서비스의 공식과 같다고 주장하지 않는다.

[AWS FlexMatch 확장 규칙](https://docs.aws.amazon.com/gameliftservers/latest/flexmatchguide/match-rulesets-components-expansion.html)의 대기시간에 따른 조건 완화를 참고해 위 수치를 정했다. AWS 서비스는 도입하지 않았다. [Cloudflare 가격·무료 한도](https://developers.cloudflare.com/durable-objects/platform/pricing/) 및 [WebSocket Hibernation](https://developers.cloudflare.com/durable-objects/best-practices/websockets/)을 확인했다. Free는 SQLite 저장 백엔드를 사용한다. 2026-10-18 사용자 대시보드에서 Workers Free Active를 확인했으며, 별도 멀티 workers.dev 도메인과 GitHub Pages Origin을 설정했다.

[Web Share API](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/share), [Android Sharesheet](https://developer.android.com/develop/ui/compose/sharing/send)의 사용자 선택 공유 방식을 사용한다. 실제 카카오톡 설치·공유·초대 링크 복귀, 모바일 브라우저 WebSocket 복귀, 토스 호스트 정책은 추가 실기기 확인이 필요하다.
