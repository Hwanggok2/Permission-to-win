# 초반 난이도 완화 — 2026-10-15

사용자가 2단계부터 너무 어렵다고 피드백했다. Excel `GameData_MVP.xlsx`의 Stages 수치를 변경하고 exporter로 Generated와 Client Resources에 반영했다. 이후 한 턴 종료와 허술한 초반 응수에 대한 추가 피드백을 반영했다. 아래 난이도 표는 초반 보호 구간 이후의 기본값이다.

## 검증

최신 추가 수정은 `Client/Evidence/opening-ranks-20261015/verification.json`을 따른다. Unity 전체 EditMode87/87, 데이터45/45, exporter `--check`, Excel69셀 차이·서식 보존 검사를 통과했다. 최소 보호 설정에서 빈 판의 양쪽 선공과6종 초기 배치를 대상으로 플레이어의 합법 선택110,008분기를 전개했다. 첫5번 AI 응수까지 조기 플레이어 승리는0이며 최대 방문 노드는2326이었다. 이는 해당 설정과 유한 구간의 자동 검사이며 모든 깊이·모든 기기에서의 불패 보장이나 사람 승률이 아니다. 재현 도구는 `Client/Tools/CheckOpeningProtection.ps1`이다.

아래 수치는 이번 초반 보호 로직을 추가하기 **이전** 난이도 조정의 검증 이력이다. 과거 봇 승률을 현재 보호 로직의 승률로 인용하지 않는다.

- 데이터 자동 검사 45/45와 exporter `--check` 통과. Generated와 Client의 3개 JSON 일치.
- Unity CoreTests 25/25 통과. 게임에 포함된 30개 단계 로드·수순·합법 AI 착수·즉시 승리·방어·탐색 예산을 검사했다. 전체 UI 검사를 다시 실행한 것은 아니다.
- 실제 C# `AiSearch`로 초반 10단계를 이전/이후 각각 256판씩 비교했다. 상대 봇은 즉시 승리·방어만 알아보고 그 밖에는 안전한 수를 무작위로 선택한다. 같은 seed 범위를 사용한 비교에서 모든 초반 단계의 봇 승리가 유지 또는 증가했다. 2단계는 18→84/256이었다. 이 수치는 사람 승률이나 체감 난이도 등급이 아니다.
- 재현 도구: `Client/Tools/CompareDifficulty.ps1`. 원본 보관·셀 차이·자동 대국·Unity 결과는 `Client/Evidence/difficulty-20261015/`에 저장한다. 최종 실행 상태는 해당 폴더의 `verification.json`을 따른다. 새 Android/WebGL 빌드와 실제 기기 플레이는 포함하지 않는다.
