# 멀티 UI 리모델링 검증

2026-10-18 KST. 저장 프리팹 구현·Unity 검증·새 웹 빌드·공개 서버에 연결한 로컬 브라우저 검증 완료. UI 커밋 `85a114e`를 포함한 `b0e2901`을 사용자가 푸시했다. Actions 성공·공개 23파일 일치 및 공개 브라우저의 친선전 결과·리매치 요청·상대 퇴장 표시를 확인했다. [공개 검증](../portrait-occlusion-20261018/README.md).

## 배치와 독립 검토

설계 세션이 [14개 와이어프레임](../../../Docs/Design/multiplayer-ui-20261018/index.html)을 만들고, 별도 검토 세션이 설계·코드·Unity 캡처를 피드백했다. 구현 담당은 저장된 OnlinePanel/RankAppRoot 프리팹과 직렬화 참조를 수정했다. 런타임은 저장된 요소의 크기와 위치만 조정한다.

- 전체 스크롤을 없애고 헤더·양측 프로필·차례·가변 정사각형 판·하단 행동으로 구성했다.
- 승패·점수와 상대 상태를 분리했다. 결과 후 다시하기/나가기는 항상 같은 줄이다. 긴 알림은 위로 공간을 늘리며 행동 위치를 유지한다.
- 무작위/친선전은 설명이 있는 카드로, 친선 방장은 레이팅 설정 아래 공유/복사를 나란히 배치했다.
- 상대 퇴장 시 대기 문구를 해제하고 나가기를 강조한다. 진행 중 퇴장 확인은 취소를 강조하고 배경 입력을 막는다. 취소 시 열 입력을 복원한다.
- 주요 행동48 CSS px·닫기44 CSS px 하한. 극단적으로 짧은 호스트 가용영역에서는 보드가 약175px로 작아진다. 활성 열 너비24px 하한을 검사했으며 일반 화면과 같은 크기를 보장하는 것은 아니다.

최종 독립 검토는 긴 계급·영어 알림, 실제 돌 배치, 1080×1920 결과, 320폭 호스트 재접속/상대 퇴장, 나가기 확인을 확인하고 추가 배치 차단 문제 없음으로 마무리했다. 설계 대비 압축 프로필44px·차례26px, 텍스트 기반 차례 강조가 최종 보정이다.

## 웹 빌드·브라우저·배포

- 초기8774 미리보기는 서버의 허용 Origin에 없어 연결되지 않았다. 서버 보안을 바꾸지 않고 기존 허용8080에서 검증했다. 브라우저 크기 override 때 도구의 좌표 입력이 부정확해 기본 창에서 실제 입력을 검증했다. 휴대폰 크기의 수치/상태 검증은 위 Unity 캡처를 따른다.
- `published-files.json`은 배포23파일 해시, `source-files.json`은 빌드 입력의 해시다. `deployment-commit.txt`는 전체 SHA다. 별도 Pages 워크트리는 커밋 후 깨끗하며 푸시하지 않았다.

```powershell
git -C C:\Users\JW\.codex\worktrees\github-pages\StageGame push origin codex/github-pages
```

사용자 푸시 후 `verify-public.py`로 새 공개 커밋·Actions·파일 해시를 확인한다. 기존 `e845e2d`의 Actions 성공·23파일 해시는 별도 마지막 돌 기록에 확인했다.

실제 휴대폰·카카오톡 공유·앱인토스 호스트 실행은 이번 검사에 포함하지 않았다. 호스트 캡처는 안전영역을 모사한 Unity 렌더링이다. 서버 배포·레이팅·매칭 규칙은 바꾸지 않았다.
