# StageGame 서버 범위

평가일: 2026-10-14 (Asia/Seoul). 초기 결정: 로컬 AI 싱글플레이 MVP에는 전용 게임 서버를 운영하지 않는다.

한 주 안에 플레이 가능한 Unity 스테이지 전략게임을 만드는 목표와 루트 `AGENTS.md`의 범위를 기준으로 평가했다. 확정 게임은 7×6 중력식 4목, 3챕터×10스테이지다. 이 폴더에는 평가 문서만 두며 서버 코드·DB·클라우드 계정·배포 구성을 만들지 않는다.

## 1. 서버 없이 시작할 수 있는 이유

MVP의 상대는 기기에서 실행되는 AI이고, 판정과 진행도는 로컬에서 관리한다. 플레이어 사이의 상태 동기화, 중앙 계정, 거래, 공정한 온라인 순위가 요구되지 않는다. 따라서 핵심 플레이를 위해 원격의 권위 있는 판정 주체나 상시 DB가 필요하지 않다.

게임 규칙과 AI 구현은 클라이언트가 담당하고, 수치·문자열은 개발 시 Excel에서 검증·생성하여 빌드에 포함한다. 이 데이터 흐름은 [GameData 형식](C:/Github/StageGame/GameData/FORMAT.md)에 정리했다. 전용 게임 서버의 배포·모니터링·장애 대응을 MVP에서 제외하면 제작 시간을 플레이 완성도와 실제 기기 검증에 사용할 수 있다.

사용자는 원스토어·토스 계정이 준비되었다고 전달했다. 이 사실을 실제 광고 SDK 연결·심사 완료로 간주하지 않는다. 플랫폼 관련 최신 정책과 연동 증거는 기획/출시 세션에서 공식 근거와 확인일을 기록한다.

## 2. MVP 기능의 위치

| 기능 | 초기 실행/저장 위치 | 후속 서버 판단 |
| --- | --- | --- |
| 게임 규칙·승패·AI 선택 | 클라이언트 로컬 | 대인전 또는 검증 가능한 온라인 경쟁을 도입할 때 재평가 |
| 스테이지·밸런스·문자열 | Excel 원본 → 검증된 클라이언트 동봉 데이터 | 앱 배포와 독립적인 데이터 갱신이 실제 필요할 때 재평가 |
| 클리어 기록·해금·설정 | 플랫폼별 로컬 저장 | 기기 간 복원/계정 동기화가 필요할 때 재평가 |
| 튜토리얼·재시도 | 클라이언트 | 기본 범위에서는 서버 불필요 |
| 광고 | 플랫폼별 광고 어댑터, 개발 시 모의 구현 | 실제 SDK와 플랫폼 계약이 서버 검증을 요구하는지 후속 확인 |
| 계정·온라인 순위·결제 | MVP에서 제외 | 도입 요구가 확정되면 별도 설계 |

로컬 기록은 사용자가 변경할 수 있다는 전제로 다룬다. 서버 없이 만든 기록을 나중에 검증된 경쟁 점수나 유료 재화의 근거로 그대로 인정하지 않는다.

## 3. 오프라인 범위와 저장

**오프라인으로 성립해야 하는 핵심 흐름**은 동봉 데이터 로드 → 스테이지 시작 → AI 대전 → 승패 → 로컬 진행 저장 → 재시작 후 이어가기다. 광고 SDK의 네트워크 상태와 무관하게 이 흐름을 검증한다.

- 로컬 저장에는 저장 스키마 버전과 필요한 최소 진행도·설정만 기록한다. 밸런스 원본을 저장 파일에 중복 소유시키지 않는다.
- 저장 실패나 손상은 조용한 전체 초기화로 숨기지 않는다. 복구/초기화 안내, 정상 저장 보존, 버전 전환 방식은 클라이언트 계약에서 정한다.
- Android와 WebGL의 저장 수명, 종료/재개, 쓰기 완료, 용량/권한 제한은 각각 실제 실행 환경에서 확인한다. 동일한 영구 보존을 가정하지 않는다.
- MVP에는 클라우드 복원이나 기기 간 동기화를 약속하지 않는다. 삭제·재설치·브라우저 데이터 초기화 시 진행 손실 가능성을 제품의 실제 저장 방식에 맞게 안내한다.
- AI 결과를 재현할 필요가 있으면 난수 시드와 콘텐츠 버전을 정한다. 특정 AI 방식이나 서버용 프로토콜을 게임 확정 전에 설계하지 않는다.

## 4. 원스토어 이후 앱인토스에서 구분할 범위

| 구분 | 평가 |
| --- | --- |
| Android 설치형 클라이언트 | 동봉 콘텐츠로 핵심 플레이를 시작하도록 설계. 실제 설치·재실행·비행기 모드 검증 필요 |
| 앱인토스용 WebGL 배포 | 웹 빌드 파일의 제공/호스팅과 게임 상태 처리 서버는 별도 책임. 현재 배포 방식·지원 조건은 출시 담당 확인 전 미정 |
| 웹 첫 로드와 저장 | 초기 파일 로드에 필요한 연결과 로드 후 게임 진행을 구분. 캐시만으로 완전 오프라인 실행을 보장한다고 표현하지 않음 |
| 실제 광고 | 광고 로드/완료 확인에는 외부 SDK/서비스 의존이 생길 수 있음. 이 문서는 실제 SDK 연결이나 광고 보상 검증 구현을 완료한 것으로 간주하지 않음 |

루트 협업 규칙에 따라 광고 실패·미충전 시 진행을 막지 않고, 보상은 검증된 완료에 대해 1회만 지급한다. 개발용 모의 성공은 실광고 검증 증거로 사용하지 않는다. 광고 어댑터와 로컬 모의 구현은 클라이언트 담당 범위다.

전용 게임 서버 운영을 생략해도 스토어, 웹 배포, 광고 관련 준비·비용이 모두 사라지는 것은 아니다. 이번 범위에서는 외부 계정 설정, 공개 배포, 유료 서비스 신청을 수행하지 않았다.

## 5. 서버 검토를 다시 시작할 조건

| 구체적인 요구 발생 시 | 검토할 최소 범위 | 선행 결정 |
| --- | --- | --- |
| 기기 변경 후 진행 복원 | 계정 식별, 저장 API, 충돌 해결, 백업/삭제 | 저장 소유권·복구 정책·플랫폼 인증 |
| 공정한 온라인 순위 | 결과 제출, 검증/재현, 중복 제출 방지, 악용 제한 | 검증 가능한 점수 정의와 보상 유무 |
| 실시간 또는 비동기 대인전 | 매치 상태, 판정 주체, 연결 복구 | 대전 방식·동시성·지연 허용 범위 |
| 유료 재화·구매 권한 | 플랫폼 검증, 지급 중복 방지, 권한 기록 | 실제 플랫폼 연동 방식과 운영 책임 |
| 앱 업데이트 없이 콘텐츠 갱신 | 버전 manifest, 파일 제공, 호환 검사, 실패 시 복귀 | 정적 호스팅만으로 충분한지 먼저 평가 |
| 플랫폼이 서버 콜백/비밀 자격증명을 요구 | 필요한 단일 연동 서비스 | 공식 요구사항·계정 준비·비밀정보 관리 주체 |

필요가 발생하면 기능별 이익, 운영 담당, 예상 이용 규모, 장애 시 게임 동작, 비용 한도를 먼저 기록한다. 현재 단계에서는 미래 가능성만으로 범용 서버 프레임워크나 더미 API를 만들지 않는다.

## 6. 완료 근거와 후속 질문

확인한 근거는 다음과 같다.

- 루트 [AGENTS.md](C:/Github/StageGame/AGENTS.md)는 로컬 AI, 서버/계정/순위/결제의 필요성 검토, 플랫폼별 광고 분리, 실행 증거 구분을 명시한다.
- SimpleGame의 Excel 원본과 Editor 생성 데이터 흐름을 정적으로 확인했다. 구조 근거와 현재 코드의 예외는 [FORMAT.md](C:/Github/StageGame/GameData/FORMAT.md)에 남겼다.
- `GameData/`에 실제 Excel, Python exporter/validator와 테스트, JSON 3개를 작성했다. 실행 결과는 [데이터 README](C:/Github/StageGame/GameData/README.md)를 따른다. 서버를 시작하거나 클라이언트를 변경하지 않았고 커밋·푸시·다른 세션 메시지를 수행하지 않았다.
- 핵심 플레이, 저장 복원, 실제 광고, Android/WebGL 테스트는 이번 문서 작업에서 실행하지 않았다.

다음 사항은 총괄의 후속 범위 확정에 필요하다.

1. 확정된 최고 해금 스테이지 저장의 플랫폼별 구현·복구·버전 호환 검증.
2. 확정된 광고 간격과 힌트 1회 보상을 실제 어댑터에 연결한 뒤 실패·중복 완료 콜백 검증.
3. 준비된 원스토어/토스 계정을 이용하는 실제 배포 방식과 플랫폼 저장·광고 조건: 출시 담당이 확인한 공식 근거를 인계.
4. 출시 첫 버전에 계정 복원·온라인 순위·결제를 포함하는지: 현재 기준은 모두 제외이며 변경 시 서버 평가를 갱신.

후속 구현의 완료 증거는 네트워크 없는 플레이, 저장 후 재시작, 광고 실패 시 진행, 중복 보상 방지, 플랫폼별 실제 실행 결과로 남긴다. 이 문서의 설계 평가와 실행 통과 기록을 구분한다.
