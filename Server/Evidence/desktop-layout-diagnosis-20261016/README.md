# PC 가로 화면 배치 오류 진단

2026-10-16 사용자 첨부 화면의 원인만 조사했다. 대상: https://hwanggok2.github.io/StageGame/

## 관찰

- 기존 저장 검사 브라우저의 기본 1280×720 화면에서 사용자 첨부와 같은 증상이 재현됐다. 도움말·설정 버튼이 커지고 제목과 `대국 시작 · 준비중`이 겹치며 단계 목록이 보이지 않는다. [재현 화면](landscape-1280x720.jpg)
- 새로고침, 저장 초기화, 게임 클릭 없이 뷰포트만 390×844로 바꾸자 단계 목록과 기존 1단계 완료/2단계 해금이 즉시 다시 보였다. [세로 전환 화면](portrait-390x844.jpg)
- DOM에서 가로 캔버스는 1280×720, 세로 캔버스는 390×844로 각각 창 전체를 채운다. 세로 전환 후 loading/error 요소 모두 hidden이다. 조회 가능한 최근 경고/오류 로그는 빈 배열이었다.
- 따라서 이번 화면 장애는 로비의 반응형 배치 오류다. 저장 데이터 로드나 Cloudflare/D1 연결을 기다리는 화면이 아니다. 진행도 API는 현재 연결되어 있지 않다.

## 코드상 원인

1. `Client/Assets/WebGLTemplates/StageGamePortrait/index.html`에서 player/canvas를 창 전체 폭·높이로 설정한다. `host-layout.js`도 visual viewport의 전체 폭·높이를 player에 적용한다. PC 가로 화면에 세로 게임 영역을 제한하는 처리가 없다. 실제 배포 페이지 DOM에서도 같은 CSS를 확인했다.
2. `Client/Assets/StageGame/Scripts/UI/SafeAreaFitter.cs:73–83`의 `widthFitTopAligned` 경로는 가로 폭만으로 배율을 정한다. `RankAppRoot.prefab`에는 이 옵션이 켜져 있으며 기준 크기는 1080×1920이다. 넓고 낮은 창에서도 세로 UI를 전체 너비에 맞춰 확대한다.
3. `Lobby.prefab:333–336`의 Stages 영역은 상하 stretch와 높이 차감 837 디자인 단위를 사용한다. 현재 코드식에 대입하면 1280×720에서 콘텐츠 높이는 `(720−8)×1080/1280 = 600.75`, 목록 높이는 `600.75−837 = −236.25`다. 목록 영역이 성립하지 않아 마스크 아래 카드가 보이지 않고 상하 고정 UI가 겹친다. 이 숫자는 코드로 계산한 값이며 브라우저에서 Unity 내부 RectTransform 값을 직접 읽은 측정값은 아니다.
4. `RankGameApp.cs:167–168`은 `multiplayer_start`와 `coming_soon`을 합쳐 해당 버튼 문구를 만들고 버튼을 비활성화한다. 화면의 `준비중`은 서버 로딩 상태가 아니라 원래 로비 하단의 준비 중 기능 문구다.

## 검증 공백과 수정 방향

앞선 저장·불러오기 검사는 390×844 세로 화면에서 통과했으며 PC 가로 배치까지 통과한 결과가 아니다. `RankMobileViewportTests.cs`의 화면 크기 집합도 세로 화면 중심이다. 이번 진단으로 가로 화면 결함을 별도 확인했다.

후속 수정은 PC 가로 창에서 세로 게임 영역의 너비를 높이에 맞춰 제한하고 중앙에 배치하거나, Unity 쪽에서 너비와 높이를 모두 고려해 콘텐츠를 맞춰야 한다. HTML 영역을 제한하는 경우 host-layout과 Unity safe-area 전달 좌표도 실제 게임 영역 기준으로 함께 맞춰야 한다. CSS만 바꾸면 된다고 단정하지 않는다.

이번에는 실행 코드·프리팹·저장 데이터·배포를 변경하지 않았다. Unity 에디터 테스트/실기기 테스트도 실행하지 않았다. 브라우저 임시 뷰포트는 검사 후 원복한다.
